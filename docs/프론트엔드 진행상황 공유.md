# LawPath 프론트엔드 진행상황 공유

> 최종 갱신: 2026-09-05
> 현재 방식: Streamlit 로컬 서버 + Mock 데이터  
> 작업 브랜치: `feature/frontend-local-mvp`

## 1. 현재 상태

Frontend는 Backend·MCP·DB 없이 단독 실행된다.

```text
사용자 → Streamlit → MockLegalService → Mock 데이터
```

핵심 기능과 보조 기능을 화면에서 확인할 수 있다. 결과는 UI 검증용 DEMO이며 실제 법률정보가 아니다.

## 2. 구현 완료 기능

### 홈·공통

- LawPath 브랜드와 세 카테고리 선택
- 도움말·알림·역할별 사용자 메뉴
- 세션 초기화
- 법률 자문·승패 예측이 아니라는 안내

### 내 사례 분석

- 대표 질문 불러오기
- 5자 미만 차단, 최대 2,000자
- 구체성·시점·상대방·증거 기준 입력 품질 안내
- 상황 요약과 핵심 쟁점
- 관련 법령과 유사 판례
- 추가 확인 질문과 주의사항
- Markdown 결과 다운로드

### 검색

- 선택 category 안의 법령 검색
- 실제 사례 검색
- 2자 미만 검색어 차단
- 검색 결과 없음 안내
- 법령·판례 상세 펼쳐보기
- 관련도가 승소 가능성이 아니라는 안내

### 보조 기능

- 쉬운 법률 용어 검색
- 필요 서류·다음 행동 체크리스트
- 진행률과 전체 초기화
- 고정 FAQ 검색·펼쳐보기
- 현재 Session 질의 이력
- 이력 다시 보기와 개별·전체 삭제

### 개발·발표

- QA 빠른 테스트
- 발표용 임대차 시나리오
- 작은 화면 기본 보정
- Streamlit 자동 메뉴와 Material 아이콘 깨짐 수정

### 역할·커뮤니티 FAQ

- QA 모드의 비회원·회원·관리자 Mock 역할 전환
- 역할별 사용자 메뉴와 보관정책 안내
- 공지형 자주 하는 질문
- 공개 사용자 질문 23건 Seed
- 답변 대기 우선, 상태별 최신순 정렬
- 분야·상태·검색 필터
- 한 페이지 10건, 이전·페이지 번호·다음 페이지네이션
- 질문 작성과 공개 동의
- 본인 질문 수정·삭제
- 답변 완료 질문의 `수정해서 다시 질문`
- 관리자 FAQ 추가·수정·삭제·공개·고정·순서 변경
- 사례 분석과 본인 사용자 질문 통합 이력
- `답변 실패` 상태 제거, `답변 대기`·`답변 완료`만 사용

### 최근 UI·통합 점검 개선

- 사이드바를 접으면 콘텐츠가 좁은 세로 띠로 남던 CSS 오류 수정
- 사이드바 펼침 상태에서만 270px 너비를 적용하고 접힌 콘텐츠는 완전히 숨김
- QA 빠른 테스트 바로 아래에 `팀 서버 연결 테스트` 추가
- Frontend·Backend·MCP는 HTTP health, DB는 TCP 포트 접근 검사
- 연결 결과별 성공·실패, 응답시간과 health 응답 표시
- DB 연결 정보의 비밀번호는 화면에서 `***`로 마스킹
- 팀 서버 주소는 환경변수로 교체 가능

## 4. 실행 방법

```powershell
cd C:\dev\aio-01-p2-team2
.\.venv\Scripts\Activate.ps1
python -m streamlit run frontend\app.py
```

접속: `http://127.0.0.1:8501`

기본 설정:

```env
FRONTEND_DATA_MODE=mock
FRONTEND_QA_MODE=false
FRONTEND_PRESENTATION_MODE=false
```

QA는 `FRONTEND_QA_MODE=true`, 발표 시나리오는 `FRONTEND_PRESENTATION_MODE=true`로 켠 뒤 Streamlit을 재실행한다.

팀 연결 확인 기본값:

```env
TEAM_FRONTEND_URL=http://192.100.200.232:8501
TEAM_BACKEND_URL=http://192.100.200.195:8000
TEAM_MCP_URL=http://192.100.200.72:8011
TEAM_DATABASE_HOST=192.100.200.99
TEAM_DATABASE_PORT=5434
TEAM_DATABASE_USER=legal_user
TEAM_DATABASE_NAME=legal_ai
```

비밀번호는 Frontend 연결 확인에 필요하지 않으며 저장하거나 표시하지 않는다.

## 7. 로컬 Mock 구현 결과

### 역할 전환

개발·QA 모드에서만 다음 역할을 전환하도록 구현했다.

```text
GUEST  비회원
USER   회원
ADMIN  관리자
```

실제 인증이 아니라 역할별 UX 검증용이다. 일반 모드에서는 역할 전환이 보이지 않는다.

### FAQ 재구성

```text
상단: 공지형 자주 하는 질문
하단: 사용자들의 공개 질문을 최신순으로 표시
```

- 누구나 질문 작성
- 공개 동의한 질문만 게시판에 표시
- 작성자만 본인 질문 수정·삭제
- 답변 전 수정
- 답변 완료 후 `수정해서 다시 질문`
- 비회원 7일 보관 예정 안내
- 회원 영구보관 예정 안내
- 관리자 공지 FAQ 작성·수정·삭제·공개·고정 Mock

### 사용자 질문 페이지네이션

- 기본 한 페이지 10건
- `이전`, 개별 페이지 번호, `다음`
- 전체 글 수와 현재 페이지 표시
- 기본 정렬은 `PENDING` 우선, 그다음 `ANSWERED`
- 같은 상태 안에서는 `created_at DESC` 최신순
- category·답변 상태 필터와 검색어 변경 시 1페이지로 이동
- 마지막 글 삭제로 현재 페이지가 비면 유효한 이전 페이지로 이동
- Mock 단계에서도 전체 목록을 한 번에 그리지 않고 페이지 단위로 잘라 표시
- 페이지 이동은 명시적인 Session callback으로 처리해 재실행 중 초기화 오류 방지

### 통합 질의 이력

- 사례 분석과 FAQ 질문 함께 표시
- 유형·category·상태 필터
- 현재 역할의 본인 이력만 표시

## 8. Mock 데이터 계약

공지 FAQ:

```text
id, category, question, answer
is_pinned, is_active, display_order
```

개인 질문:

```text
id, owner_type, owner_id, category
conversation_type, title, content
status, answer
visibility, display_name
created_at, updated_at, expires_at
```

규칙:

- 비회원 질문에 화면용 만료시각 표시
- 회원 질문은 만료 없음
- `visibility=PUBLIC`이고 공개 동의한 질문만 게시판에 노출
- 공개 목록에서는 작성자를 닉네임 또는 `비회원`으로 표시
- 개인정보 입력 경고와 화면용 마스킹 시나리오 포함
- 본인 Mock 질문만 수정·삭제
- 답변 완료 질문 변경 시 새 질문 생성
- 실제 개인정보·실제 법률 결론 사용 금지
- DEMO 표시 유지

## 9. 현재 하지 않는 작업

- 실제 회원가입·로그인
- 비밀번호·JWT·Cookie
- Redis·PostgreSQL·Supabase 연결

- 실제 권한 검증

회원·관리자·보관기간은 향후 동작을 확인하기 위한 Mock임을 화면에 명시한다.

## 10. 로컬 Mock 완료 기준

- 기존 핵심 기능 회귀 없음
- 역할별 화면 차이
- 공지 FAQ와 최신 사용자 질문 게시판 분리
- 개인 질문 CRUD
- 최신순 정렬과 페이지네이션
- 답변 후 다시 질문
- 통합 질의 이력
- 보관정책 안내
- 관리자 FAQ 관리 UX
- 일반 모드에서 역할 전환 숨김
- 자동 테스트와 주요 해상도 확인

기능 자동 테스트는 완료했다. 주요 해상도와 예시화면 Pixel 비교는 브라우저 수동 확인 항목으로 남아 있다.

## 12. 실제 Backend 연동 방식

Mock을 삭제하지 않고 설정으로 전환한다.

```env
FRONTEND_DATA_MODE=api
BACKEND_API_URL=http://BACKEND_PC_IP:8000
```

```text
MockLegalService → Backend Client
```

두 Service가 같은 View Model을 반환해야 Component를 다시 작성하지 않아도 된다.

연동 순서:

1. Backend `/health`
2. 현재 사용자와 역할
3. FAQ 조회와 개인 질문 CRUD
4. 사례 분석과 법령·판례
5. 질의 이력 저장·재조회
6. 회원·비회원 소유권
7. Backend·MCP·DB 장애 화면

## 13. 팀 공유용 요약

```text
현재
→ Backend 없이 Frontend 전체 흐름 확인 가능
→ 법률 결과는 Mock

다음
→ 역할별 UX·FAQ 개인 질문 CRUD·통합 이력 Mock
→ 예시 화면 디자인 보정

팀 합류 후
→ 확정 API에 맞춰 Mock Service를 Backend Client로 전환
```

## 14. 현재 팀 서버 연결 점검 결과

QA 모드에서 다음 경로를 한 번에 확인할 수 있다.

```text
Frontend /_stcore/health
→ Backend /health
→ MCP /health
→ DB TCP :5434
```

2026-09-05 현재 개발 PC에서 제공된 Backend·MCP·DB 주소는 제한시간 안에 응답하지 않았다. 이는 UI 검사 기능의 실패가 아니라 서버 미실행, 방화벽 또는 서로 다른 네트워크 가능성을 의미한다. 각 담당자가 서버를 `0.0.0.0`에 바인딩하고 Windows 사설망 방화벽을 연 뒤 다시 검사해야 한다.
