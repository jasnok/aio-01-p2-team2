# LawPath 프론트엔드 진행상황 공유

> 최종 갱신: 2026-09-07
> 현재 방식: Streamlit 로컬 서버 + Mock 데이터  
> 작업 브랜치: `feature/faq-visibility-comments`

## 1. 현재 상태

Frontend는 Backend·MCP·DB 없이 단독 실행된다.

```text
사용자 → Streamlit → MockLegalService → Mock 데이터
```

핵심 기능과 보조 기능을 화면에서 확인할 수 있다. 결과는 UI 검증용 DEMO이며 실제 법률정보가 아니다.

## 2. 구현 완료 기능

### 홈·공통

- LawPath 브랜드와 세 카테고리 선택
- 도움말·알림·역할별 사용자 메뉴
- 세션 초기화
- 법률 자문·승패 예측이 아니라는 안내

### 내 사례 분석

- 대표 질문 불러오기
- 5자 미만 차단, 최대 2,000자
- 구체성·시점·상대방·증거 기준 입력 품질 안내
- 상황 요약과 핵심 쟁점
- 관련 법령과 유사 판례
- 추가 확인 질문과 주의사항
- Markdown 결과 다운로드

### 검색

- 선택 category 안의 법령 검색
- 실제 사례 검색
- 2자 미만 검색어 차단
- 검색 결과 없음 안내
- 법령·판례 상세 펼쳐보기
- 관련도가 승소 가능성이 아니라는 안내

### 보조 기능

- 쉬운 법률 용어 검색
- 필요 서류·다음 행동 체크리스트
- 진행률과 전체 초기화
- 고정 FAQ 검색·펼쳐보기

### FAQ 사용자 질문 공개·비밀글과 댓글

- 질문 작성 시 `🔒 비밀글로 작성`을 선택할 수 있으며 개인정보 보호를 위해 기본값은 비밀글
- 공개글은 제목·본문·댓글을 누구나 확인하고 누구나 댓글 작성 가능
- 비밀글은 제목만 모두에게 표시하고 본문·댓글은 작성자와 관리자만 접근 가능
- 비회원 질문과 댓글은 각각 4~20자 비밀번호로 수정·삭제 권한 확인
- 회원은 현재 Mock 로그인 Session으로 본인 댓글 수정·삭제
- 관리자는 비밀글 확인과 운영 목적의 댓글 삭제 가능
- 사용자 댓글을 공식 법률 답변과 구분하는 안내 표시
- 댓글 등록 알림 생성, 비밀글 알림에는 본문·댓글 원문 미포함
- 서비스 계층 권한 테스트와 실제 Streamlit 공개글·댓글 작성 흐름 자동 테스트 추가

상세 수동 점검은 `FAQ 공개·비밀글 댓글 테스트 체크리스트.md`를 따른다.
- 현재 Session 질의 이력
- 이력 다시 보기와 개별·전체 삭제

### 개발·발표

- QA 빠른 테스트
- 발표용 임대차 시나리오
- 작은 화면 기본 보정
- Streamlit 자동 메뉴와 Material 아이콘 깨짐 수정

### 역할·커뮤니티 FAQ

- QA 모드의 비회원·회원·관리자 Mock 역할 전환
- 역할별 사용자 메뉴와 보관정책 안내
- 공지형 자주 하는 질문
- 공개 사용자 질문 23건 Seed
- 답변 대기 우선, 상태별 최신순 정렬
- 분야·상태·검색 필터
- 한 페이지 10건, 이전·페이지 번호·다음 페이지네이션
- 질문 작성 시 4~20자 게시글 비밀번호와 확인 입력
- 공개 게시판에는 제목·분야·상태·작성시각만 표시
- 질문 내용과 답변은 작성자 Session + 게시글 비밀번호 확인 후 표시
- 게시글 비밀번호 원문 대신 Mock Hash만 저장
- 공개 검색에서 비공개 질문 내용을 제외하고 제목만 검색
- 비회원 소유자를 브라우저 Session별 고유 ID로 분리
- 본인 질문 수정·삭제
- 답변 완료 질문의 `수정해서 다시 질문`
- 관리자 FAQ 추가·수정·삭제·공개·고정·순서 변경
- 사례 분석과 본인 사용자 질문 통합 이력
- `답변 실패` 상태 제거, `답변 대기`·`답변 완료`만 사용

### 최근 UI·통합 점검 개선

- 사이드바를 접으면 콘텐츠가 좁은 세로 띠로 남던 CSS 오류 수정
- 사이드바 펼침 상태에서만 270px 너비를 적용하고 접힌 콘텐츠는 완전히 숨김
- QA 빠른 테스트 바로 아래에 `팀 서버 연결 테스트` 추가
- Frontend·Backend·MCP는 HTTP health, DB는 TCP 포트 접근 검사
- 연결 결과별 성공·실패, 응답시간과 health 응답 표시
- DB 연결 정보의 비밀번호는 화면에서 `***`로 마스킹
- 팀 서버 주소는 환경변수로 교체 가능

### Agent 실행 UX·예외 처리 개선

- 질문 검증부터 답변 생성까지 6단계 Agent 진행 상태 표시
- 분석 처리 중 버튼 비활성화 구조 적용
- 정상, 검색 결과 없음, 공식 근거 부족 Mock 상태 제공
- Backend·MCP·DB 연결 실패, 시간 초과, 응답 형식 오류, 사용자 취소 시나리오 제공
- 실패 단계, 쉬운 오류 설명, 다음 행동, 오류 코드 표시
- 법령 L1·L2와 판례 C1·C2 형식으로 답변 근거 구분
- 공식 원문 연동 전 상태와 관련도 점수의 의미 안내
- 후속 질문 추천·직접 입력·대화 표시·새 분석 시작
- 예상 결과와 실제 결과를 비교하는 Agent Mock 평가 표
- 640px 이하 화면의 Column 줄바꿈과 진행 단계 크기 보정

### Mock 회원가입·로그인과 역할 검증

- 헤더 사용자 메뉴에 로그인·회원가입·비밀번호 재설정 화면 추가
- 회원·관리자 DEMO 계정 제공
- 이메일 형식, 닉네임, 비밀번호 조건, 비밀번호 확인 검증
- 이메일·닉네임 중복과 필수 약관 동의 검증
- 회원가입 성공 시 Mock 회원 역할로 자동 로그인
- 로그인 실패, 로그아웃과 계정 존재 여부를 노출하지 않는 재설정 안내
- 관리자 로그인 시에만 FAQ 관리 메뉴 노출
- 비회원의 관리자 화면 직접 접근 차단 유지
- 비밀번호 원문을 계정 데이터에 저장하지 않고 성공 후 입력 Session 키 제거
- 실제 인증이 아니라는 경고와 개인정보 입력 금지 안내

### Mock 알림 센터

- 상단 배지에 읽지 않은 알림 개수 표시
- 읽지 않은 알림 우선, 각 묶음 안에서는 최신순 정렬
- 개별 읽음, 모두 읽음, 개별 삭제와 읽은 알림 삭제
- 알림에서 사례 분석·FAQ·질의 이력 관련 화면으로 이동
- 사례 분석 완료·검색 결과 없음·근거 부족·오류 알림 자동 생성
- FAQ 사용자 질문 등록 알림 자동 생성
- Mock 회원가입·로그인·로그아웃 알림 자동 생성
- QA 모드에서 답변 완료·만료 예정·연결 오류 알림 생성
- 정보·성공·주의·오류 중요도를 글자와 아이콘으로 구분
- 현재 Session에만 저장되며 실제 외부 전송이 없다는 안내

## 4. 실행 방법

```powershell
cd C:\dev\aio-01-p2-team2
.\.venv\Scripts\Activate.ps1
python -m streamlit run frontend\app.py
```

접속: `http://127.0.0.1:8501`

기본 설정:

```env
FRONTEND_DATA_MODE=mock
FRONTEND_QA_MODE=false
FRONTEND_PRESENTATION_MODE=false
```

QA는 `FRONTEND_QA_MODE=true`, 발표 시나리오는 `FRONTEND_PRESENTATION_MODE=true`로 켠 뒤 Streamlit을 재실행한다.


최근 검증 결과:

```text

Streamlit health: HTTP 200
Presentation mode: PASS
```

```powershell

```

세 카테고리, 분석·검색·빈 결과·입력검증·상세보기·체크리스트·FAQ·이력·다운로드·발표 모드와 연결 점검 UI를 확인했다. 저장소 전체 테스트 수는 다른 파트의 테스트 추가에 따라 달라질 수 있으므로 커밋 시점 결과를 함께 공유한다.

Agent 진행 순서, 9개 Mock 실행 상태, 오류별 다음 행동, 근거 없는 결과 방지와 Expected/Actual 평가도 자동 테스트에 포함했다. 체크리스트 기반 사용자 흐름을 추가 검증해 총 38개가 통과했다. 이 과정에서 새 분석 초기화 시 발생하던 Streamlit 상태 변경 오류를 발견하고 Callback 방식으로 수정했다. 수동 확인 순서는 **docs/프론트엔드 Mock 테스트 체크리스트.md**를 따른다.

Mock 인증은 Service 단위 검증과 Streamlit 사용자 흐름 테스트 15개를 추가했다. 회원·관리자 로그인, 회원가입, 로그아웃, 잘못된 입력, 권한별 메뉴와 비밀번호 원문 제거를 확인했다.

FAQ 질문 보호 테스트에서는 제목 공개, 내용 비공개, 잘못된 게시글 비밀번호 차단, 작성자 잠금 해제, 잠금 해제 후 수정·삭제, 공개 검색의 내용 제외와 비회원 Session 소유권 분리를 확인했다.

Mock 알림 테스트에서는 생성·최신순 정렬·읽지 않은 개수·개별 및 전체 읽음·삭제·관련 화면 이동과 분석·질문 이벤트 연동을 확인했다.

## 7. 로컬 Mock 구현 결과

### 역할 전환

개발·QA 모드에서만 다음 역할을 전환하도록 구현했다.

```text
GUEST  비회원
USER   회원
ADMIN  관리자
```

실제 인증이 아니라 역할별 UX 검증용이다. 일반 모드에서는 역할 전환이 보이지 않는다.

### FAQ 재구성

```text
상단: 공지형 자주 하는 질문
하단: 사용자들의 공개 질문을 최신순으로 표시
```

- 누구나 질문 작성
- 공개 동의한 질문만 게시판에 표시
- 작성자만 본인 질문 수정·삭제
- 답변 전 수정
- 답변 완료 후 `수정해서 다시 질문`
- 비회원 7일 보관 예정 안내
- 회원 영구보관 예정 안내
- 관리자 공지 FAQ 작성·수정·삭제·공개·고정 Mock

### 사용자 질문 페이지네이션

- 기본 한 페이지 10건
- `이전`, 개별 페이지 번호, `다음`
- 전체 글 수와 현재 페이지 표시
- 기본 정렬은 `PENDING` 우선, 그다음 `ANSWERED`
- 같은 상태 안에서는 `created_at DESC` 최신순
- category·답변 상태 필터와 검색어 변경 시 1페이지로 이동
- 마지막 글 삭제로 현재 페이지가 비면 유효한 이전 페이지로 이동
- Mock 단계에서도 전체 목록을 한 번에 그리지 않고 페이지 단위로 잘라 표시
- 페이지 이동은 명시적인 Session callback으로 처리해 재실행 중 초기화 오류 방지

### 통합 질의 이력

- 사례 분석과 FAQ 질문 함께 표시
- 유형·category·상태 필터
- 현재 역할의 본인 이력만 표시

## 8. Mock 데이터 계약

공지 FAQ:

```text
id, category, question, answer
is_pinned, is_active, display_order
```

개인 질문:

```text
id, owner_type, owner_id, category
conversation_type, title, content
status, answer
visibility, display_name
content_visibility, password_hash
created_at, updated_at, expires_at
```

규칙:

- 비회원 질문에 화면용 만료시각 표시
- 회원 질문은 만료 없음
- `visibility=PUBLIC`인 질문의 제목과 기본 정보만 게시판에 노출
- 내용과 답변은 본인 Session과 게시글 비밀번호 확인 후 노출
- 공개 검색은 제목만 대상으로 처리
- 게시글 비밀번호 원문은 Session과 질문 데이터에 저장하지 않음
- 공개 목록에서는 작성자를 닉네임 또는 `비회원`으로 표시
- 개인정보 입력 경고와 화면용 마스킹 시나리오 포함
- 본인 Mock 질문만 수정·삭제
- 답변 완료 질문 변경 시 새 질문 생성
- 실제 개인정보·실제 법률 결론 사용 금지
- DEMO 표시 유지

## 9. 현재 하지 않는 작업

- 실제 회원가입·로그인
- 비밀번호·JWT·Cookie
- Redis·PostgreSQL·Supabase 연결
- Legal MCP·LLM 호출
- 실제 7일 자동 만료
- 실제 권한 검증

회원·관리자·보관기간은 향후 동작을 확인하기 위한 Mock임을 화면에 명시한다.

## 10. 로컬 Mock 완료 기준

- 기존 핵심 기능 회귀 없음
- 역할별 화면 차이

- 개인 질문 CRUD
- 최신순 정렬과 페이지네이션
- 답변 후 다시 질문
- 통합 질의 이력
- 보관정책 안내
- 관리자 FAQ 관리 UX
- 일반 모드에서 역할 전환 숨김
- 자동 테스트와 주요 해상도 확인

기능 자동 테스트는 완료했다. 주요 해상도와 예시화면 Pixel 비교는 브라우저 수동 확인 항목으로 남아 있다.

## 11. 팀 합류 후 확인할 Frontend 계약

- Backend PC 실제 URL과 CORS 적용 여부
- 로그인·로그아웃·현재 사용자 API 응답 일치 여부

- 인증 만료·접근 금지·비회원 만료 오류 확인
- Opaque Bearer Session Token 전달과 만료 처리
- Pagination 응답 필드와 정렬 기준 확인

## 12. 실제 Backend 연동 방식

Mock을 삭제하지 않고 설정으로 전환한다.

```env
FRONTEND_DATA_MODE=api
BACKEND_API_URL=http://BACKEND_PC_IP:8000
```

```text
mock 모드: 화면 → MockLegalService
api 모드:  화면 → ApiLegalService → BackendClient → Backend
```

두 Service가 같은 View Model을 반환해야 Component를 다시 작성하지 않아도 된다.

2026-09-07 구현 상태:

- `FRONTEND_DATA_MODE=mock|api` 선택 지원
- API 사례 분석 연결 및 Streamlit Session ID·중복 방지 Key 전달
- API 법령·판례·법률 용어 검색 연결
- Backend Evidence 응답을 기존 법령·판례 카드 형식으로 변환
- Backend 연결·Timeout·계약 오류를 사용자용 메시지로 변환
- `.env` 설정과 분리된 Mock 회귀 테스트 및 API Adapter 단위 테스트
- 실제 Backend `192.100.200.195:8000` 호출과 Streamlit 사례 분석 화면 확인 완료

2026-09-07 추가 API 연결:

- 회원가입·로그인·로그아웃·비밀번호 재설정·현재 사용자
- 공개 FAQ와 관리자 FAQ CRUD
- 사용자 질문 목록·작성·상세·잠금 해제·수정·삭제
- 공개·비밀글 댓글 목록·작성·수정·삭제
- 비회원 Guest ID와 회원 Bearer Session Token 전달
- 통합 질의 이력 조회·삭제
- 알림 조회·읽음·전체 읽음·삭제

Token은 Streamlit Session에만 보관하며 파일·Local Storage·로그에는 기록하지 않는다. `mock` 모드는 기존 화면 회귀 테스트를 위해 그대로 유지한다.

연동 순서:

1. Backend `/health`
2. 현재 사용자와 역할
3. FAQ 조회와 개인 질문 CRUD
4. 사례 분석과 법령·판례
5. 질의 이력 저장·재조회
6. 회원·비회원 소유권
7. Backend·MCP·DB 장애 화면
