# 성공 지연 통계의 표본 계약

이전 `benchmark_analysis.summarize()`는 검증 결과가 없어도 빈 목록의 `all()`이 참이어서 완료·보완 요청을 성공으로 집계했습니다. 검증 문자열·정수도 참처럼 평가될 수 있고, 음수나 비유한 지연도 통계에 들어갈 수 있었습니다.

성공 표본은 오류가 없고 완료 또는 보완 상태이며 다음 계약을 모두 만족해야 합니다.

- 현재 스모크의 공통 검사 7개: 멱등 접수, 실제 모드, 실시간 SSE 종료, 종료 상태, 소유자 분리, SSE 재생, 실시간/재생 순서 일치.
- 생성 답변은 인용 검사, spans 모드는 답변/주장 일치 검사. 도구 시간 기록이 있는 요청은 조기 근거 이벤트 검사도 필요합니다.
- 모든 제공 검사값은 정확한 bool이고 참이어야 합니다. 검사 누락·빈 객체·부분 검사·잘못된 타입은 통과가 아닙니다.
- 전체 지연은 유한한 비음수 int/float여야 하며 bool은 제외합니다. 제공된 첫 근거 시간도 같은 형식이고 전체 지연 이하여야 합니다.

제외 요청은 requests 분모와 기존 상태·생성 상태 집계에 남깁니다. 검사 실패·미검증·비정상 검사·불완전 검사·비정상 시간의 개수를 구분합니다. `completed_llm` 통계는 이 계약을 통과한 생성 답변만 포함하며 보완 요청을 섞지 않습니다. p95의 최소 표본 20개 규칙은 유지합니다.

새 요약에는 `success_contract=live-smoke-checks-v2`를 기록하여 이전 집계와 구분합니다.

자식 명령의 종료값이 0이어도 빈 출력이나 한 개라도 불합격 요청이 있으면 벤치마크 명령은 실패 종료합니다. 원본 파일과 요약의 원본 파일 참조는 보존합니다. 기존 역사적 측정 파일을 수정하거나 새 성능 수치로 바꾸지 않았습니다. 예전 형식에 필수 검사가 없다면 새 계약으로는 불완전 표본입니다.

검증은 합성 표본으로 빈/부분/잘못된 검사값, 잘못된 시간, 상태별 통계, 자식 성공 종료의 잘못된 출력과 원본 보존을 확인합니다. API나 모델 호출을 다시 측정한 결과는 아닙니다.
