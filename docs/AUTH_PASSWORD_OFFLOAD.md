# 인증 비밀번호 계산의 이벤트 루프 분리

회원가입의 scrypt 해시 생성과 로그인의 비밀번호 검증을 `asyncio.to_thread`로 실행한다. 기존 해시 형식, 이메일·표시 이름 정규화, 사용자 조회 → 비밀번호 확인 → 활성 상태 확인 순서와 오류 종류는 유지한다. DB 작업은 기존 비동기 경로에 남는다.

## 검증

- 새 회귀 테스트 7개: 회원가입·로그인의 별도 스레드 실행과 계산 대기 중 이벤트 루프 진행, DB에 해시만 전달, 없는 사용자 검증 생략, 비활성 사용자의 오류 우선순위, 계산 오류 전파 및 DB 쓰기 방지.
- 기존 실제 scrypt 인증·HTTP 세션 테스트를 포함한 관련 테스트: 11개 통과.
- 전체 테스트 및 CI 결과는 연결된 PR에 기록한다.

## 범위

비밀번호 계산 자체를 줄이거나 scrypt 강도를 변경하지 않았다. 로그인 지연시간 개선율은 측정하지 않았다. 기본 executor의 작업 스레드를 사용하며 별도의 인증 대기열 제한은 추가하지 않는다. 요청 취소가 이미 실행 중인 스레드 계산을 중단하지는 않는다.
