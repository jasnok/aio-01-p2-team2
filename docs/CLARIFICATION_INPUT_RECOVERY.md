# 추가 정보 입력의 실패 복구

정보 부족 결과의 보완 입력 폼은 이전에 제출 즉시 입력을 비웠습니다. Streamlit이 브라우저에 전달하는 폼 프로토콜의 `clear_on_submit=true`를 확인했습니다. 제출 후 연결 실패나 입력 검증 오류가 발생해도 사용자 입력이 지워지는 설정입니다.

폼은 자동 초기화를 하지 않습니다. 오류에서는 작성 내용·기존 분석·기존 명시적 재시도 상태를 보존합니다. 성공한 결과로 전환할 때만 다음 렌더링에서 입력을 비웁니다. 위젯 생성 후 세션 값을 직접 바꾸는 대신, 성공 표시를 다음 렌더링 시작에서 소비해 Streamlit의 위젯 상태 규칙을 지킵니다. 새 분석과 인증 변경도 그 표시를 제거합니다.

자동 재시도를 추가하지 않았습니다. 사용자가 같은 입력으로 다시 제출하면 기존 분석 실행 복구 경로를 사용합니다. 성공한 후속 결과와 대화 메시지는 한 번만 반영합니다. 새 입력으로 재제출하는 기존 동작과 2000자 합산 제한은 유지합니다.

검증 범위는 브라우저에 보내는 폼 설정, 합성 연결 실패 후 같은 질문의 명시적 재제출, 성공 후 다음 보완 단계의 빈 입력, 짧거나 긴 입력의 보존 및 호출 차단, 새 분석 시작 시 상태 초기화입니다. 실제 브라우저 촬영이나 모델 호출을 수행했다는 의미는 아닙니다.

대상 테스트 4개와 실제 Redis·PostgreSQL 통합을 포함한 전체 로컬 테스트 494개 통과·4개 외부 테스트 제외를 확인했습니다. 프론트엔드 Docker 빌드·재생성 후 health HTTP 200, 측정 요약 일치 검사와 `git diff --check`도 통과했습니다.
