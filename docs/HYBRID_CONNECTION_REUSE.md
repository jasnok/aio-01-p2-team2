# 하이브리드 후보 조회의 DB 연결 공유

벡터 후보와 키워드 후보 조회는 이전에 두 연결에서 실행했습니다. 기존 벡터 SQL을 커서 기반 내부 함수로 분리하여 단일 조회 메서드도 같은 SQL을 사용하고, 하이브리드 후보 조회는 한 연결·커서에서 두 단계를 실행합니다. 단일 조회 API와 키워드별 SQL·제한·순서·점수·융합은 유지합니다. 연결 풀이나 새 병렬 작업은 추가하지 않았습니다.

PostgreSQL READ COMMITTED의 문장별 스냅샷은 유지되므로 실행 중 데이터가 바뀌면 고정 스냅샷의 동등성을 보장하지 않습니다. 한 트랜잭션에서 키워드 실패 시 연결이 정리되며 전체 검색은 실패합니다. 벡터 결과를 독립 성공으로 반환하지 않습니다.

## 로컬 짝 비교

실제 DB의 저장된 벡터를 사용하여 임베딩/API/모델 호출 없이 후보 조회만 비교했습니다. 범주별 준비 2쌍 후 측정 10쌍을 번갈아 실행하고, 준비 포함 12쌍의 벡터·키워드 전체 결과 dict가 일치했습니다.

| 범주·문서 유형 | 두 연결 중앙값 | 한 연결 중앙값 |
|---|---:|---:|
| 주거·법령 | 162.44ms | 128.66ms |
| 근로·판례 | 111.97ms | 58.79ms |
| 소비자·상담사례 | 273.50ms | 226.36ms |

연결 수는 두 개에서 한 개로 줄었습니다. 저장된 문서 벡터를 사용한 단계 측정으로 실제 질문 임베딩, 검색 관련성, 전체 상담 지연이나 p95의 개선을 입증하지 않습니다. 원시 표본·결과 해시·벡터 해시·관련 코드 해시·Python/패키지·DB 문서 수는 [측정 JSON](../output/portfolio/hybrid-connections.json)에 있습니다. 측정 당시 작업 트리는 수정 중이었으며 코드 출처를 해시로 기록했습니다.

`scripts/benchmark_hybrid_connections.py --output <새 파일>`로 재현하며 기존 결과를 덮어쓰지 않습니다. 호스트 DB 접속 URL을 환경변수로 설정해야 합니다. 첫 실행의 pgvector 객체 변환 메서드 오류는 실제 `to_list()`로 수정한 뒤 전체 세 범주를 재실행했습니다.

연결 하나·유형별 분기·키워드 순서·벡터/키워드 실패 시 정리를 합성 테스트로 검증했습니다. 실제 DB 전체 결과의 동등성은 위 짝 비교에서 확인했습니다. 실제 Redis·PostgreSQL 통합을 포함한 전체 로컬 회귀는 547개 통과·4개 외부 테스트 제외였습니다. MCP Docker 빌드·재생성 후 도구 6개 조회, 서비스 5개 healthy, 측정 코드 해시 일치와 요약 자료 검사도 확인했습니다. CI는 PR의 최종 커밋 결과를 별도로 확인합니다.
