# 발표 모드의 엔지니어링 측정 화면

`FRONTEND_PRESENTATION_MODE=true`인 작업 화면의 발표 패널에서 **엔지니어링 측정 결과**를 펼칩니다. 일반 서비스 흐름과 데모 준비 버튼은 유지하며 측정 결과 화면은 API 요청을 보내지 않습니다.

화면은 SDK 클라이언트 생성/재사용과 키워드 DB 조회의 중앙값·표본 수·준비 횟수·Python 버전을 보여줍니다. 키워드 비교는 결과 동등성 비교 쌍도 표시합니다. 측정 범위를 선택해 표와 그래프를 확인하고 숫자 요약 JSON을 내려받을 수 있습니다. 환경 기록은 설치 패키지 수·버전 불일치 수를 보여줍니다. 이는 기록된 환경 검증 결과이며 현재 실행 중인 환경을 자동 점검한 결과는 아닙니다.

전체 상담 지연, 모델 추론 시간, p95, 사람에 의한 법률 정확도는 검증하지 않았다고 화면에 표시합니다. 원본에 측정 시점의 커밋·데이터 버전이 없으므로 미기록으로 표시합니다. SDK와 DB의 서로 다른 측정 범위를 합산하거나 법률 정확도 향상으로 표현하지 않습니다.

## 재생성

```powershell
.\.venv\Scripts\python.exe scripts/build_portfolio_evidence.py
.\.venv\Scripts\python.exe scripts/build_portfolio_evidence.py --check
```

생성기는 기존 `output/portfolio`의 허용된 측정/환경 JSON 5개를 읽습니다. 중앙값을 원시 표본에서 다시 계산하고 공개 값과 비교하며 표본 수·결과 동등성을 확인합니다. 질문·검색어·문서 원문·패키지 상세·자격 증명은 생성 결과로 옮기지 않습니다.

`frontend/data/portfolio-evidence.json`만 런타임에 포함됩니다. Docker에서 `output` 전체를 제외하는 기존 정책은 유지합니다. CI는 `--check`로 원본과 생성된 요약의 일치 여부를 검사합니다. 파일의 SHA-256은 키 정렬·공백 제거한 UTF-8 JSON 내용 기준이므로 Windows/Linux 줄바꿈 차이에 영향을 받지 않습니다.

자료가 없거나 형식 검증에 실패하면 오류 안내를 표시하고 표·다운로드를 제공하지 않습니다. 화면 테스트는 두 측정 범위 전환, 제한 안내, 다운로드 및 파일 누락 대응을 확인합니다. 측정 재실행이나 추가 모델 호출을 수행하지 않습니다.

검증 결과: 대상 테스트 5개, 전체 로컬 테스트 448개 통과·4개 외부 검증 건너뜀입니다. Docker 빌드와 생성 자료 로드(측정 4행·환경 3건), Streamlit HTTP 200을 확인했습니다. 실제 Redis·PostgreSQL 통합 테스트를 포함하며 새 모델 호출은 없었습니다.
