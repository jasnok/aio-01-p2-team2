# 게시판·댓글·개인 이력·알림의 소유자 경계

## 문제

게시판 비밀글은 owner_id만 비교했다. 합성 회원 비밀글에 같은 ID의 GUEST를 넣으면 비밀 본문을 읽는 것을 재현했다. 댓글 소유자 판정과 이력/알림 키도 동일한 ID 영역을 사용했다.

## 변경

작성한 게시글과 댓글에 owner_role을 보관하고, 공통 owns_record 검사에서 `(회원 또는 게스트, 문자열 ID)`를 비교한다. USER와 ADMIN은 같은 회원 계정 영역이다. 다른 영역에서는 같은 ID와 올바른 게시글/댓글 비밀번호를 알아도 작성자로 인정하지 않는다.

- 비밀글 본문·댓글 열람과 댓글 작성은 작성자 또는 관리자만 허용한다.
- 게시글 잠금 해제·수정·삭제·재질문과 댓글 수정·삭제는 새 소유자 검사를 사용한다.
- 공개글 열람과 관리자 열람/삭제·감사 기록 정책은 유지한다. 관리자는 다른 사람 댓글을 수정할 수 없다.
- 이력·알림의 저장/읽기/수정/삭제, 잠금 해제 기록은 소유자 영역을 포함한 키를 사용한다.
- 게시글 답변/댓글 알림은 기록에 저장된 작성자 역할로 수신 영역을 결정한다.
- 기존 동기 분석이 만든 이력과 알림도 같은 영역에 저장한다.
- owner_role은 내부 저장 필드이며 댓글의 공개 응답에는 추가하지 않는다.

## 검증

동일 ID의 회원/게스트를 양방향으로 바꿔 HTTP API를 검사한다. 비밀글·댓글 접근, 올바른 비밀번호를 가진 타 영역의 편집/삭제/잠금 해제/재질문, 공개 댓글 is_owner, 이력 상세/삭제, 알림 읽음/삭제/일괄 처리 모두 확인한다. 정상 작성자의 조회·댓글 수정, 공개글 열람, 관리자 비밀글 조회와 감사 기록도 확인한다. 기존 demo 로그인·FAQ·게시판 테스트도 유지한다.

## 자료와 한계

게시판·댓글·이력·알림은 기존처럼 프로세스 메모리 저장소다. DB 구조나 기존 저장 대화를 변경하지 않는다. demo 초기 자료는 사용자와 FAQ이며 유지한다. 게시글/댓글/이력/알림의 영속 저장이나 프로세스 재시작 후 복구를 새로 구현한 것은 아니다.

이전 코드가 작성한 owner_role 없는 메모리 기록은 소유자를 추측해 허용하지 않는다. 역할 불명 기록의 내용은 지우지 않지만 작성자 접근은 거부한다. 새 코드 배포는 전체 API 프로세스에 적용해야 한다. 게스트 헤더를 인증 토큰으로 바꾸거나 게스트 간 ID 도용을 차단한 것은 아니며, 공개 배포의 전체 보안 검증 완료를 의미하지 않는다. 실제 개인정보나 유료 API 없이 합성 자료로 검사하며 성능 향상 수치는 주장하지 않는다.
