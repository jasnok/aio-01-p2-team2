# 실행 상태 조회 경합 수정

## 문제와 수정

오래된 `running` 상태를 읽은 조회 요청이 중단 여부를 판단하는 동안 작업자가
`completed`를 저장할 수 있었다. 기존 조회는 이후 `failed`를 무조건 저장하여
완료 결과를 유실시켰다. 합성 테스트로 이 순서를 재현했다.

조회 타임아웃 처리를 Redis Lua의 비교 후 저장으로 변경했다. 조회한 원문이
현재 값과 같을 때만 실패 상태를 기록한다. 다른 작업자가 갱신했다면 최신 값을
반환하고, 키가 만료됐다면 `None`을 반환한다. `KEEPTTL`로 기존 만료 시점을 유지한다.
API 응답과 SSE 이벤트 형식은 그대로 유지한다.

## 검증

- 단위 테스트: 중단 상태 기록, 완료/진행 상태 갱신 및 만료 경합, 연결 오류의 정보 비노출.
- 실제 로컬 Redis: GET 직후 완료 저장을 끼워 넣어 결과 보존 확인.
- 실제 로컬 Redis: 중단 전후 남은 TTL 비교, 만료된 키의 재생성 방지 확인.
- 통합 테스트는 `RUN_REDIS_INTEGRATION`에 테스트 Redis URL을 명시할 때 실행한다.
  무작위 전용 키만 생성·삭제하며 다른 데이터는 변경하지 않는다. URL은 출력하지 않는다.

## 참고 프로젝트와 설계 판단

`C:\aidevs`의 live execution state 예제는 TTL 상태 저장과 작업 큐를 구분한다.
handoff guard 및 bounded retry 예제는 명시적인 전이와 종료 제한을 강조한다.
`C:\mini_multi_agent`의 역할 계약과 Supervisor 예제는 역할별 입출력 검증 및
검증 대상 revision을 명시한다. 이 원칙을 참고하되 새 Supervisor 호출을 추가하기보다
현재 결정적 Workflow의 실제 상태 경합을 먼저 해결했다.

## 범위와 다음 과제

이번 수정은 **조회 타임아웃 쓰기**의 경합을 해결한다. 일반 작업자 저장 전체에
revision 검사나 종료 상태 보호를 제공하지 않는다. 작업자 저장의 전이 계약,
오래된 작업자의 쓰기 거부, Redis 통합 테스트의 CI 실행은 후속 과제다.
Redis 스냅샷은 작업 큐가 아니며 프로세스 재시작 후 분석 자동 재개를 보장하지 않는다.
