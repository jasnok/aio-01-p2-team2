# 추가 정보 요청의 보완 질문 계약

입력 판단이 needs_clarification이면 검색을 중단하고 사용자에게 보완 질문을 보여준다.
모델이 공백이나 원문 반복만 반환하면 기존 정규화가 이를 제거하면서 질문 없는 중단
결과가 만들어졌다. 합성 출력으로 이 경우를 재현했다.

정규화 후 유효한 보완 질문이 최소 1개 있는지 검사한다. 질문이 없으면 형식 오류로
기존 최대 2회·전체 timeout 재시도 경로를 사용한다. 모두 실패하면 IntakeAssessmentError를
반환한다. 임의 질문을 추가하거나 검색을 강행하지 않는다. sufficient와
proceed_with_caution은 보완 질문이 없어도 기존대로 검색 가능하다.

검증은 합성 Provider로 공백·빈 목록·원문 반복의 재시도, 두 번 실패 시 종료,
정상 보완 질문 및 검색 가능한 상태를 확인한다. validation_completed 이벤트는
유효한 판단 후 한 번만 발행한다. 실제 모델 판단 정확도나 법률 품질을 측정하는
테스트가 아니며 유료 모델 호출도 하지 않는다. 이번 수정은 내부 IntakeAgent의
출력 계약을 강화하며 공개 응답 스키마는 변경하지 않는다.
