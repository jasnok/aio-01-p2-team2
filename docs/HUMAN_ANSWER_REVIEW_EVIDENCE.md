# 사람 답변 품질 검토의 원문 근거와 출처

기존 `review_latency.py`는 질문·답변·인용과 빈 점수를 내보냈지만 대조할 근거 원문은 원본 파일에서 별도로 찾아야 했습니다. 새 양식(schema_version=2)은 비교 실험에서 사용한 고정 후보 근거의 ID·제목·내용과 출처 제목·종류·URL을 함께 제공합니다. 모델에 선택된 문맥은 이 후보 목록의 일부일 수 있으므로 실제 모델 입력 전체를 복원했다는 뜻은 아닙니다.

생성 전 원본 파일 바이트의 SHA-256을 비교 기록과 대조합니다. 각 실행의 원본 시나리오 번호·질문·범주·설정을 확인하고 중복 실행 파일을 거부합니다. 개별 실행 파일의 SHA-256은 별도 대응표에 기록합니다. 원본 파일 경로는 비교 명령 당시와 같은 저장소 실행 위치를 기준으로 해석하므로 자료를 이동했다면 같은 원본을 찾을 수 있어야 합니다.

Git의 Windows/Linux 체크아웃은 LF/CRLF를 바꿀 수 있습니다. 원본 SHA는 현재 바이트와 LF 또는 CRLF로 복원한 바이트 중 하나와 일치해야 하며, 줄바꿈 이외의 변경은 허용하지 않습니다. 원본의 기록된 SHA와 별도로 `normalized_lf_sha256`, 개별 실행의 `sample_sha256_lf`를 남겨 같은 내용을 플랫폼 사이에서 대조할 수 있습니다.

Windows의 역슬래시 경로 구분자도 플랫폼에 맞게 해석하며 기록된 원본 경로 문자열은 보존합니다. 다른 PC의 절대 경로 자체를 자동으로 찾는 기능은 아닙니다.

검토 양식은 설정·모델 메타데이터와 실행 파일명을 복사하지 않습니다. 설정명·파일명·실행 해시는 검토자에게 전달하지 않는 별도 `*-key.json` 대응표로 분리합니다. 이는 절차상 블라인드이며 저장소의 대응표 접근을 기술적으로 차단하는 기능은 아닙니다. 실행 성공/실패와 답변 출처(생성·대체·없음·알 수 없음)는 표시하지만 사람 판정을 대신하지 않습니다. reviewer·scores·notes는 비워둡니다. 모델 사용 여부가 기록되지 않았다면 생성·대체로 추정하지 않습니다.

## 생성과 보존

```powershell
.\.venv\Scripts\python.exe scripts/review_latency.py output/latency/answer-comparison --output-prefix quality-review-new
```

위 이름으로 이미 생성했다면 새 이름을 선택합니다. 검토 JSON 또는 대응표 중 하나라도 있으면 실패하여 기존 작업을 보존합니다. 두 출력 모두 새 파일로만 생성하며 기존 사람 점수나 이전 양식을 덮어쓰는 옵션은 제공하지 않습니다. 유효성 검사는 출력 생성 전에 끝냅니다.

실제 기존 답변 비교 14건에서 별도 이름으로 생성해 근거 3건 또는 8건 포함, 생성 답변 13건·대체 안내 1건, 사람 점수 없음 상태를 확인했습니다. 이는 과거 실험 자료를 재구성한 검증이며 새 모델 실행이나 사람이 평가한 품질 수치가 아닙니다. 기존 v1 자료도 보존했습니다.

준비된 [검토 양식](../output/latency/answer-comparison/quality-review-evidence.json)을 평가자에게 전달하고, 대응표는 채점이 끝난 뒤 비교를 집계하는 담당자가 사용합니다. 원문 법률 자료와 고정된 실험 질문을 포함하며 개인정보가 있는 새 실험 자료는 공유 전에 별도로 확인해야 합니다.

전체 로컬 테스트는 실제 Redis·PostgreSQL 통합을 포함하여 533개 통과·4개 외부 테스트 제외였습니다. 이후 LF/CRLF와 경로 구분자 호환 검사를 추가한 최종 대상 테스트 15개도 통과했습니다. 측정 요약 일치 검사와 diff 공백 검사도 통과했습니다.

Linux Python 컨테이너의 읽기 전용 저장소에서 원본·실행 파일을 LF로 재생해 임시 폴더에 생성했고, 공개된 14건 양식과 대응표 내용이 정확히 같은 것을 확인했습니다. 처음에는 Windows 경로 구분자로 원본 조회가 실패해 경로 해석을 수정한 뒤 재검증했습니다.

합성 테스트는 원문 포함·설정 정보 분리·빈 라벨, 원본 해시 및 질문/범주/설정 불일치·시나리오 번호·중복 거부, 기존 검토/대응표 보존, 실패 및 사용 정보 누락의 표시를 확인합니다. 실제 품질 비교와 기본 모델 설정 결정은 사람 채점 후 별도 진행해야 합니다.
