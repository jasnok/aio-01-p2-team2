# Frontend HTTP 장애 경계

공통 `_request()`는 HTTPX 요청 오류를 `BackendClientError(BACKEND_REQUEST_FAILED)`로 변환합니다. 응답 읽기·요청 쓰기·프로토콜·프록시·압축 해석 오류가 UI 예외로 빠지던 경로를 처리합니다. 기존 timeout/connect 코드와 HTTP 상태별 안내는 유지합니다. 원문 네트워크 예외 대신 사용자용 안내만 표시합니다.

전송 중단은 서버가 요청을 처리하지 않았다는 뜻이 아닙니다. 오류 안내는 변경 요청이 이미 처리되었을 수 있음을 설명하고 기존 작업이나 이력을 먼저 확인하도록 합니다. `_request()`는 GET·POST 모두 자동 재전송하지 않습니다.

분석의 명시적인 재시도는 기존 pending 요청 키를 보존합니다. 생성 응답을 받지 못했다면 같은 키로 요청하고, 실행 ID를 받은 뒤 조회가 실패했다면 새 실행을 생성하지 않습니다. 서버의 기존 idempotency·소유자 계약을 계속 사용합니다. 이 동작은 외부 모델의 정확히 한 번 처리나 결제 취소를 보장하지 않습니다.

SSE는 같은 실행의 네트워크·응답 해석 오류를 기존 최대 3회 연결 범위에서 처리하고 마지막 snapshot 조회로 종료 결과를 확인합니다. 새 분석을 생성하거나 재연결 한도를 늘리지 않습니다. 잘못된 JSON/이벤트 계약은 재연결로 숨기지 않습니다. 오류 HTTP 본문 자체가 끊겼다면 원문을 표시하지 않고 상태 코드 기반 안내를 사용합니다.

대상 테스트 73개는 GET/POST 오류의 단일 호출, 기존 오류 코드, 안전한 안내, Streamlit pending 키/실행 ID 유지, 오류 본문 중단, SSE 연결 한도를 검증합니다. 합성 HTTP 장애를 사용하며 실제 모델 호출은 없습니다.
