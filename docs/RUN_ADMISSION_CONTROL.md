# 분석 접수 제한과 종료 정리

기존 start_run은 요청마다 task를 만들어 대기하는 합성 요청 25개가 모두 활성화됐다.
프로세스별 슬롯을 도입해 Redis 예약을 기다리는 요청도 포함하여 실행 수를 제한한다.
기본 AGENT_RUN_MAX_CONCURRENCY=4는 단일 프로세스 데모의 보수적인 시작 설정이며
실제 모델 부하 실험으로 최적값을 입증한 값은 아니다. 1~100 범위에서 조정할 수 있다.

용량 초과는 503 ANALYSIS_CAPACITY_EXCEEDED와 Retry-After: 2를 반환한다.
대기 큐를 만들지 않으며 클라이언트가 재시도할 수 있다. 이미 존재하는 멱등 요청은
슬롯을 소비하지 않고 반환한다. Redis 예약 전에 기존 예약을 조회하지만 신규 요청
경합은 기존 원자적 reserve_run이 결정한다. 예약 경합의 중복·오류·취소는 슬롯을 해제한다.
task는 완료·실패·취소 시 슬롯을 해제하며 shutdown은 활성 task를 취소하고 기다린 뒤
모델 클라이언트를 닫는다. 슬롯 해제는 중복 호출해도 한 번만 적용된다.

합성 테스트의 제한 2에서 요청 25개 중 2개 접수, 23개 거부, 종료 후 슬롯 0을 확인한다.
실제 LLM·검색 호출 없이 검증하며 비용·전체 응답 속도 개선률은 주장하지 않는다.
API 계약 테스트는 포화 상태의 멱등 재조회와 초과 요청의 임시 상태 정리, Redis
예약 실패·중복에서 슬롯 누수가 없는지 검증한다. 기존 SSE 테스트도 유지한다.

범위는 비동기 /api/agent-runs 실행이며 동기 분석 API와 용어 대화는 이 슬롯을 쓰지
않는다. 여러 API 프로세스의 전체 한도는 각 프로세스 한도의 합이다. Redis 전역 lease,
사용자별 요청 제한, 내구성 큐나 재시작 후 자동 재개는 제공하지 않는다. 취소된 실행은
기존 조회의 중단 판정으로 실패가 확인되며 즉시 terminal 저장을 보장하지 않는다.
참고 자료의 bounded execution 원칙을 적용하되 Supervisor나 새 작업 큐 의존성은 추가하지 않았다.
