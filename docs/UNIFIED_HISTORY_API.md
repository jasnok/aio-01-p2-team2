# 저장 분석·용어 대화의 공통 이력 API

실제 `/api/saved-conversations` 목록은 각 행의 `type`으로 분석과 법률 용어 대화를 구분합니다. 기존 UI는 이 목록을 모두 분석으로 바꾸고, 구현되지 않은 `/api/legal-terms/conversations`를 추가 호출했습니다. 용어 이력이 잘못 표시되고 별도 조회가 404가 되는 문제를 실제 서버 계약 모양의 혼합 목록 테스트에서 재현했습니다.

회원 목록·상세·삭제는 기존 공통 저장 이력 API만 사용합니다. 목록 유형은 `HistoryPageView`에서 검증한 뒤 보존합니다. 용어 상세는 채팅 메시지로 표시하며 삭제 전 확인을 유지합니다. 페이지당 목록 요청은 기존 두 경로에서 한 경로로 줄지만, 전체 응답 시간 개선률을 측정한 변경은 아닙니다. 캐시나 신규 서버 API는 추가하지 않았습니다.

상세에 명시된 유형과 `id` 또는 `conversation_id`가 선택한 항목과 다르면 표시하지 않습니다. 모델 분석의 `request_id`는 저장 대화 ID와 다른 식별자이므로 비교하지 않습니다. 서버의 기존 소유자 검사는 그대로 적용됩니다. 상세 조회 실패는 이전 상세를 지우고 안내하며, 삭제 실패는 항목과 확인 상태를 유지합니다.

유형 필터는 공통 목록의 현재 페이지에 적용합니다. 서버 페이지 정보가 없는 이전 목록의 로컬 페이지 처리도 유지합니다. 비회원 임시 이력은 기존 별도 API를 사용합니다.

테스트는 혼합 목록의 두 유형, 용어 상세·삭제 경로, 목록 요청 한 번, 페이지 전달과 필터, 삭제 실패 상태, 상세 유형/ID 불일치를 확인합니다. 기존 이력 응답의 잘못된 유형 거부와 인증 변경 시 상태 초기화 테스트도 유지합니다. 실제 모델 호출은 필요하지 않습니다.

검증 기록: 대상 테스트 16개 통과, 실제 Redis·PostgreSQL 통합을 포함한 전체 로컬 테스트 490개 통과·4개 외부 테스트 제외. 프론트엔드 Docker 빌드·재생성 및 health HTTP 200, 측정 요약 일치 검사와 diff 공백 검사도 확인했습니다.
