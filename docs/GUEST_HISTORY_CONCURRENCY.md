# 게스트 임시 이력 동시 저장

## 문제와 재현

게스트 분석과 용어 설명은 같은 Redis 이력 배열에 저장된다. 두 요청이 같은 이전
배열을 GET한 뒤 각각 SET하면 마지막 저장이 먼저 저장된 결과를 지운다.
합성 barrier 재현에서 두 결과 중 한 건만 남았다.

## 변경

읽은 Redis 원문과 현재 원문을 Lua에서 비교하여 일치할 때만 새 배열을 저장한다.
충돌하면 최신 배열을 다시 읽고 해당 run_id를 교체한 뒤 저장을 시도한다.
최대 8회만 시도하며 재시도 사이에 1~7ms를 기다린다. 모두 충돌하거나 연결 장애가
발생하면 SessionStoreUnavailableError를 반환한다. 저장에 실패했는데 성공을 알리지 않는다.

Python JSON 원문을 저장하여 결과의 중첩 빈 배열을 보존한다. 기존 키·TTL·최신 저장
우선 순서·동일 run_id 교체 정책은 유지한다. 메모리 모드는 기존 lock을 사용한다.

## 검증

실제 Redis에서 서로 다른 GuestSessionService 두 인스턴스가 같은 이전 상태를 읽도록
barrier를 적용했다. 두 저장이 모두 성공하고 충돌 한 번이 발생하며 두 결과가 남는지
확인한다. 분석과 용어 설명 혼합, 동일 run_id 교체, TTL, 게스트 격리와 삭제도 검증한다.
별도 테스트로 재시도 8회 소진 및 연결 오류의 민감 정보 비노출을 검증한다.

CI의 RUN_REDIS_INTEGRATION 설정으로 실행하며 무작위 테스트 전용 키만 정리한다.
회원 DB나 실제 사용자 이력은 변경하지 않는다.

## 한계

성공한 저장끼리의 덮어쓰기 유실을 방지한다. 높은 경합에서 저장 성공을 무조건
보장하지 않으며 전체 이력 배열 읽기·쓰기 비용은 이력 길이에 비례한다.
clear는 진행 중 분석을 취소하는 기능이 아니다. 삭제가 끝난 뒤 진행 중 작업이 새
저장을 시작하거나 재시도하면 이력이 다시 생길 수 있다. 세션 폐기와 실행 취소의
통합은 별도 과제다. Lua 비교·저장은 Redis의 원자성을 사용하며 작업 큐를 추가하지 않는다.
