# 용어 답변 저장 후 후속 질문의 대화 유지

기존 저장 버튼은 답변 항목에 저장 결과만 반영했습니다. 다음 질문은 별도 세션의 `terms_conversation_id`를 읽어 저장된 대화 문맥을 요청하므로 최초 저장 후에도 ID가 전달되지 않았습니다. 또한 서버는 소유자 검사를 통과한 대화 ID를 받아도 선택 저장을 하지 않는 응답에서 ID를 반환하지 않아 후속 질문에서 다시 연결을 잃었습니다.

저장 컴포넌트는 성공 결과를 반영한 뒤 선택적 `on_saved` 콜백을 호출합니다. 용어 대화 화면은 여기서 다음 질문에 사용할 ID를 갱신합니다. 분석 저장 화면의 동작은 동일합니다. 저장 실패 시 콜백을 호출하지 않으며 기존 대화 상태를 보존합니다. 새 대화와 사용자/분석 변경의 기존 초기화 경로는 계속 ID를 지웁니다.

회원의 저장하지 않는 후속 응답에도 요청의 대화 ID를 반환합니다. 앞선 문맥 조회에서 소유자와 법률 용어 대화 범주를 확인하며, 새 요청은 ID가 없습니다. 응답의 `saved=false`·`storage=none`은 그대로여서 문맥 연결이 자동 저장을 의미하지 않습니다. 게스트 응답과 저장 선택 경로는 기존 정책을 유지합니다.

회귀 테스트는 수정 전 두 경로의 ID가 `None`이 되는 실패를 재현했습니다. Streamlit 테스트는 최초 저장→두 번 후속 질문→새 대화 시작, 저장 실패→명시적 재시도의 상태를 확인합니다. API 테스트는 소유자 검사를 통과한 문맥·응답·저장 준비 기록의 같은 ID와 저장하지 않는 상태를 확인합니다. 실제 모델 호출은 하지 않습니다.

전체 로컬 검증은 실제 Redis·PostgreSQL 통합 테스트를 포함하여 484개 통과·4개 외부 테스트 제외였습니다. backend·frontend Docker 빌드와 재생성 후 두 서비스의 health HTTP 200, 측정 요약 일치 검사와 `git diff --check`도 확인했습니다.
