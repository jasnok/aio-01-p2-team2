## 2. 자동 통합 테스트 다시 실행하기


정상이면 테스트 2개가 모두 `PASSED`로 끝난다. 평소 전체 테스트에서는 실제 서버가 없어도 되도록 이 검사는 자동으로 `SKIPPED`된다.

## 3. 사람이 Frontend에서 확인할 항목

### 3.1 사례 분석

1. `http://192.100.200.232:8501`을 연다.
2. `임대차·주거`를 선택한다.
3. `계약이 끝났는데 보증금을 돌려받지 못했습니다.`를 입력한다.
4. `사례 분석하기`를 한 번 누른다.

- [ ] 처리 중 안내가 보인 뒤 결과 화면으로 바뀐다.
- [ ] 상황 요약, 핵심 쟁점과 답변이 읽기 쉽게 표시된다.
- [ ] Backend가 Mock이면 화면에서도 DEMO임을 알 수 있다.
- [ ] 버튼을 빠르게 여러 번 눌러도 결과가 중복 생성되지 않는다.
- [ ] Backend 터미널에 같은 요청이 불필요하게 여러 번 기록되지 않는다.

자동 테스트는 화면이 깨지지 않고 결과가 만들어지는 것까지 확인한다. 버튼을 실제로 빠르게 누르는 행동과 Backend 로그 건수는 사람이 확인해야 한다.

### 3.2 법령·판례 검색

1. 왼쪽 `법 검색`에서 `보증금`을 검색한다.
2. 왼쪽 `실제 사례`에서 `보증금 반환`을 검색한다.

- [ ] 결과가 있으면 카드가 깨지지 않고 표시된다.
- [ ] 결과가 0건이면 오류 대신 `검색 결과 없음` 안내가 보인다.
- [ ] 법령의 제목·조문·출처가 알맞은 위치에 보인다.
- [ ] 판례의 사건번호·법원·선고일·관련도가 알맞은 위치에 보인다.
- [ ] 관련도가 승소 확률이 아니라는 안내가 보인다.

현재 Backend Mock은 법령·판례를 0건으로 반환할 수 있다. 이 경우 `검색 결과 없음`이면 정상이다. 실제 카드 모양은 MCP·DB 데이터가 연결된 뒤 다시 확인한다.

### 3.3 쉬운 법률 용어

1. 왼쪽 `쉬운 법률 용어`로 이동한다.
2. 전체 목록에서 `내용증명`이 보이는지 확인한다.
3. `보증금`을 검색한다.

- [ ] 빈 검색어일 때 기본 용어 목록이 표시된다.
- [ ] 검색어를 넣으면 해당 용어만 표시된다.
- [ ] 결과가 없을 때 안내 문구가 표시된다.

### 3.4 오류 안내

Backend 담당자와 시간을 맞춘 뒤에만 서버를 잠시 중지하고 사례 분석을 한 번 실행한다.

- [ ] 긴 Python 오류 대신 `Backend에 연결할 수 없습니다`라는 안내가 보인다.
- [ ] Backend 재실행 후 새로고침하면 다시 요청할 수 있다.
- [ ] 실패한 요청이 성공한 Mock 결과로 바뀌어 표시되지 않는다.

다른 팀원이 Backend를 사용 중이면 이 검사는 생략한다.

## 4. 인증·게시판·이력·알림 수동 확인

- [ ] 회원 계정으로 로그인하면 헤더가 `회원`으로 바뀐다.
- [ ] 로그아웃하면 비회원으로 돌아가고 기존 Token을 다시 사용할 수 없다.
- [ ] 회원가입 시 비밀번호 확인과 필수 동의를 검사한다.
- [ ] FAQ 공지 내용이 Backend Swagger의 조회 결과와 같다.
- [ ] 공개글은 다른 사용자도 본문과 댓글을 볼 수 있다.
- [ ] 비밀글은 작성자와 관리자만 본문·댓글을 볼 수 있다.
- [ ] 비회원은 질문·댓글 비밀번호로 본인 글을 수정·삭제할 수 있다.
- [ ] `질의 이력`에서 본인 질문이 보이고 삭제할 수 있다.
- [ ] 질문·댓글 작성 후 Backend 알림이 보이며 읽음·삭제가 작동한다.
- [ ] 관리자 로그인 시 FAQ 관리 메뉴가 나타나고 CRUD가 작동한다.

현재 Backend 자체가 메모리 Mock 저장소를 사용하므로 Backend 재시작 후 데이터가 사라질 수 있다. PostgreSQL·Redis 연결 전까지는 영속 저장 완료로 판단하지 않는다.

## 5. 테스트 중 오류가 났을 때 기록

| 기능 | 입력값 | HTTP 상태 | Frontend 화면 | Backend 로그 | 담당 |
|---|---|---:|---|---|---|
| 예: 사례 분석 | 보증금 미반환 | 422 | 입력 오류 | 필드 누락 | Frontend/Backend |

가능하면 화면 캡처와 Backend 터미널의 `request_id`를 함께 남긴다. 비밀번호·Session Token·개인정보는 기록하지 않는다.
