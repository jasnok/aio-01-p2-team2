## 1. 프로젝트 정의

사용자가 **임대차·주거 / 근로·임금 / 중고거래·소비자** 중 하나의
카테고리를 선택하고 자신의 사례를 자연어로 입력하면, 카테고리별 Legal AI
Agent가 MCP Tool을 선택하여 PostgreSQL + pgvector RAG DB에서 관련 법령과
유사 판례를 검색하고, 실제 판례의 판결 결과와 공식 원문 출처를 포함해
설명하는 법률 정보 검색 서비스이다.

이 서비스는 법률 자문이나 사용자의 승소 가능성을 예측하는 서비스가
아니다. 이미 선고된 실제 판례의 판결 결과는 근거와 함께 표시할 수
있지만, 사용자의 사건이 승소/패소할 것이라고 예측하거나 단정하지 않는다.

## 2. 지원 카테고리

1.  **임대차·주거 (`housing`)**
    -   전·월세 보증금 반환
    -   계약 종료·중도 해지
    -   임대인과의 분쟁
2.  **근로·임금 (`labor`)**
    -   임금 체불
    -   퇴직금 미지급
    -   부당해고
    -   근로조건 불일치
3.  **중고거래·소비자 (`consumer`)**
    -   대금 지급 후 미배송
    -   설명과 다른 물품
    -   환불 거부
    -   거래 사기 의심

사용자는 먼저 카테고리를 선택하고, 선택 후 해당 기능과 사례 입력 화면이
나타나도록 한다.

## 11. MCP Server 구조

현재 담당 문서에 정의된 구조:

``` text
legal_mcp/
├─ _ollama_pgvector.py
├─ mcp_server.py
├─ mcp_server1.py
├─ mcp_server2.py
└─ mcp_server3.py
```

`_ollama_pgvector.py`:

-   pgvector 연결
-   질문 Vector화
-   pgvector 데이터 조회

`mcp_server.py`는 공통 진입점/통합 서버 역할을 권장한다.

`mcp_server1.py ~ mcp_server3.py`의 정확한 책임은 업로드된 구조 문서에
명시되어 있지 않다. 2차 회의의 "MCP 서버 나눠서 하기"와 세 카테고리를
연결한다면 다음 매핑을 후보로 둘 수 있다.

``` text
mcp_server1.py → 임대차·주거
mcp_server2.py → 근로·임금
mcp_server3.py → 중고거래·소비자
```

**이 매핑은 구현 전 팀 확정이 필요하다.**

## 17. Chunking / Embedding

법령:

-   조문 단위 우선
-   긴 조문만 문단 분리
-   법령명·조문번호·시행일 유지

판례:

``` text
사건 정보
핵심 쟁점
판단 요지
판결 내용
결론 / 판결 결과
```

초기 권고:

-   500\~800 tokens
-   overlap 50\~100 tokens

Embedding 입력에 문서유형, 카테고리, 사건명/법령명, 사건번호/조문번호,
법원, 제목을 포함한다.

## 18. Hybrid Search

1.  category 필터
2.  document_type 필터
3.  정확한 법령명/조문 → SQL/Keyword 우선
4.  자연어 사례 → pgvector similarity
5.  Keyword + Vector 결합
6.  동일 문서 중복 청크 제거
7.  임계값 미달 제거
8.  Top 3 반환

초기값:

``` text
final_score = vector_score × 0.7
            + keyword_score × 0.3
```

평가 결과로 조정한다.

## 20. Agent 실행 정책

Agent가 결정:

-   어떤 Tool이 필요한가
-   유사 판례 검색이 필요한가
-   판례 상세 조회가 필요한가
-   법령 원문이 필요한가
-   추가 질문이 필요한가
-   언제 종료할 것인가

Backend가 강제:

-   category 허용값
-   Tool allowlist
-   Pydantic 검증
-   top_k 제한
-   최대 Tool 호출
-   Timeout
-   오류 표준화
-   출처 없는 결과 제외
-   최종 응답 Schema 검증

권고:

-   Tool 최대 3회
-   동일 Tool + 동일 인자 반복 금지
-   전체 Timeout 60초
-   MCP Timeout 15초
-   재검색 1회
-   실패하면 추측하지 않고 추가 질문

Redis는 MUST 완료 후 적용한다.

후보 용도:

-   최근 대화 문맥
-   session 질의 이력
-   반복 검색 캐시

``` text
legal:session:{session_id}:messages
```

API Key, 비밀번호, 불필요한 개인정보 원문은 저장하지 않는다.

SSE는 일반 JSON API 완성 후 시간이 있을 때 적용한다.

## 34. 최종 개념 정리

``` text
법원 Open API
= 공식 판례 원천 데이터

PostgreSQL
= 법률 원문과 metadata 저장

pgvector
= 의미적으로 비슷한 판례 검색

RAG
= 관련 법령·판례를 검색해 LLM에 근거 제공

MCP
= Agent가 사용할 법률 검색 Tool 제공

Agent
= 카테고리에 따라 어떤 Tool을 사용할지 판단

LLM
= 검색된 근거를 이해하기 쉽게 설명

Backend
= 전체 요청·Agent 실행·응답 관리

Frontend
= 사용자의 입력과 결과 표시
```

최종 목표는 AI가 법률 결론을 임의로 만들어 주는 서비스가 아니라,
**사용자의 사례를 이해하고 공식 법률 자료와 유사 판례를 찾아 실제 근거와
출처를 중심으로 설명하는 Legal Research Agent**를 구현하는 것이다.
