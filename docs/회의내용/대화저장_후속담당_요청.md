# Frontend 완료 범위와 후속 담당 요청

## Frontend

- Sidebar 완전 제거. 선택 분야 아래 내 사례 분석/FAQ/질의 이력 상단 메뉴.
- QA 빠른 테스트 삭제. 별도 연결 점검/발표 패널은 켜더라도 본문에만 표시.
- 검색 메뉴는 제거하되 기존 Backend/MCP 검색 API는 보존.
- 법령/판례/상담사례는 150자 미리보기 + 상세보기. 출처 버튼/기관 메타데이터/출처 목록/다운로드 출처 필드 제거.
- 원본 API Evidence·출처 데이터는 내부 검증용으로 유지. 문서 자체의 법령명·법원·사건번호는 내용 식별 정보로 유지.
- SSE는 내부 Tool·원시 message를 그대로 출력하지 않고 사용자용 문구 및 일반 fallback을 사용.
- DB 저장이나 이전 대화 조회가 완료됐다고 표시하지 않음. 현재 후속 질문은 원질문+추가정보 전달.

## Backend — 최소 확장 제안 (아직 미구현)

기준 검토: origin/develop f8c477d. 현재 SSE/이력은 MemoryStore이고
Conversation Repository는 없음. agent registry는 설정 매핑이므로 저장소로 사용하지 않음.

1. 기존 DB pool을 재사용하는 Conversation Repository/Service 추가.
2. saved_conversations/saved_messages/saved_message_sources 재사용.
3. 동기 분석과 agent_run_service가 공통 저장 함수를 사용하도록 연결. 완료 이벤트 전에 저장 결과 확정.
4. category, 새 question, 선택적 conversation_id 요청 계약. 응답에 conversation_id를 선택적으로 추가하여 기존 클라이언트 호환.
5. 인증 Actor로 소유권 확인. 전달받은 ID만으로 타인 대화 접근 불가.
6. 후속 질문은 최근 완료 2~3턴 + 최초 질문 + 직전 보완 질문 + 필요한 근거 ID만 조회.
   Context 길이 상한을 두고 전체 대화/문서 원문을 매번 보내지 않음.
7. 기존 답변은 대화 참고이며 법률 근거로 신뢰하지 않음. 필요한 법률 자료는 MCP 재검색.
8. 기존 /history API 유지, 상세조회로 이전 결과 복원 추가. Backend에서 최신 상태·저장 여부를 반환.
9. 실패/재시도/중복 완료의 메시지 중복 저장을 고유 request/run 키로 방지.
10. 현재 AnswerAgent는 정형 답변 구성임. DB 조회를 실제 LLM 대화 생성 완료로 표현하지 않음.

SSE tool/id/event 계약은 유지. message는 사용자 문장으로 변경.
Frontend는 알려지지 않은 Tool도 일반 문구로 표시하므로 원시 오류·내부 이름 노출 금지.

## DB — 최소 migration 제안

- 003_saved_conversations.sql은 명시적 저장을 전제함. 우선 사용자 선택 저장 방식 권장.
- 실제 로그인 Actor와 users.anonymous_key 중심 테이블 매핑 우선 확정.
- Conversation: category, 저장 상태, 만료시각(보관 정책 결정 후).
- Message: 실행/request 식별자, 순서, 처리 상태, 분석 결과 JSON 스냅샷 검토.
- conversation_id/순서 인덱스, 실행별 중복 방지 제약.
- 기존 데이터·원문 출처는 삭제하지 않음. 출처 제거는 사용자 표시 범위.
- 비회원 7일 정책은 자동 만료 작업까지 구현 후 표시. 기존 개인정보/보관 동의 없이 영구 자동 저장하지 않음.

## MCP

대화 저장 책임 추가 불필요. 법률 검색 Tool/Repository 유지.
재검색 시 문서·청크 ID와 원본 근거를 Backend에 계속 반환.

## 다음 통합 순서

정책·소유권 계약 → DB migration → Repository/Service → 공통 저장
→ Context 조회 → Frontend 저장 선택/대화 ID/이력복원 연결 → E2E.
현 단계에서 Frontend에 작동하지 않는 저장 버튼이나 임의 conversation_id를 만들지 않음.
