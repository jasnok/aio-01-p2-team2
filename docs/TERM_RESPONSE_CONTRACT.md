# 법률 용어 목록·검색 응답 계약

## 문제와 변경

용어 화면은 검색 응답의 `term`·`description`을 직접 읽고 목록의 각 항목을 두 변수로 언패킹한다. 기존 클라이언트는 두 구조를 검증하지 않아, 필수 키 누락이나 잘못된 목록 쌍이 화면 예외로 이어졌다.

프론트엔드 공통 모델에 `LegalTermView`, `TermSearchView`, `CategoryTermsView`를 추가했다. 용어와 설명은 비어 있지 않은 엄격한 문자열이어야 하고, 목록의 각 쌍은 정확히 두 요소여야 한다. 목록의 카테고리도 요청한 분야와 일치해야 한다. 필수 배열이 누락되거나 잘못된 형태이면 기존 `CONTRACT_MISMATCH`로 변환한다.

기존 `ApiLegalService`가 이 예외를 사용자 안내로 바꾸므로 화면에 오류 안내가 나타나고 렌더링이 중단되지 않는다. 검증 후 원래 응답을 반환해 카테고리의 이름·서류 등 다른 필드를 제거하지 않는다. 정상 데이터와 빈 목록·빈 검색 결과는 계속 지원한다.

## 검증 범위

`frontend/tests/test_term_response_contract.py`에서 실제 클라이언트 함수에 잘못된 응답을 주입한다. 필수 필드, 배열 형태, 목록 쌍의 길이, 숫자·불리언·null·빈 문자열, 카테고리 불일치를 검사한다.

Streamlit `AppTest`로 목록과 검색의 두 오류 경로를 각각 실행해 예외 없이 오류 안내가 표시되는지 확인한다. 수정 전 해당 화면은 언패킹 오류와 `KeyError`로 중단되었으며, 응답 계약 테스트를 포함해 25개 테스트가 실패했다. 정상 응답의 전체 필드·서비스의 튜플 구조·원본 입력 불변성도 검증한다.

이 계약은 안내 사전 응답 구조를 검증한다. 법률적 타당성을 평가하거나 공식 검색 근거·LLM 대화 응답 계약을 대체하지 않는다. 모델 호출이나 공유 캐시를 추가하지 않는다.
