# 문맥 전용 PostgreSQL 조회

## 변경

분석·용어 대화의 문맥은 최초 사용자 메시지와 최근 3개를 사용하지만 기존 restore는
모든 메시지와 답변 snapshot까지 가져왔다. restore_context를 추가해 소유자를 검증한
뒤 필요한 최대 4행의 id·role·content만 조회한다. 기존 메시지 순서 및 최초 질문
인덱스를 활용하며 스키마를 변경하지 않는다. 이력 복원의 전체 restore는 유지한다.

## 실제 로컬 측정

PostgreSQL 16.15, 연결 단위 임시 테이블, 합성 메시지별 snapshot payload 1KB.
각 경로를 한 번 준비 조회한 뒤 순서를 번갈아 20회 측정했다.

| 메시지 수 | 전체 / 문맥 반환 행 | 전체 / 문맥 직렬화 크기(byte) | 전체 / 문맥 조회 중앙값(ms) |
|---:|---:|---:|---:|
| 10 | 10 / 4 | 12,472 / 292 | 1.707 / 1.689 |
| 1,000 | 1,000 / 4 | 1,226,443 / 304 | 16.097 / 2.153 |
| 10,000 | 10,000 / 4 | 12,291,946 / 310 | 163.938 / 2.780 |

원본 샘플과 저장소 소스 SHA256은
[측정 JSON](../output/context/saved-context-benchmark.json)에 보관했다.
시간은 저장소 호출의 경과 시간이며 Python 결과 직렬화 시간·LLM·HTTP API를 제외한다.
크기는 Python 결과의 JSON 직렬화 크기이며 PostgreSQL wire 전송량 자체가 아니다.
10개 메시지의 시간 차이는 매우 작다. 합성 로컬 환경의 측정이므로 실제 서비스의
전체 응답 속도 개선률이나 모든 환경의 일정한 지연을 보장하지 않는다.

## 검증

실제 PostgreSQL에서 빈 대화, 1~4개 대화, 질문 없이 시작한 대화, 사용자 질문 없는
대화, 반복 내용, 1,000개 메시지를 검증했다. 문자 제한 0·1·12·3,000에서 기존 전체
복원으로 선택한 문맥과 동일하다. 다른 소유자·없는 대화·잘못된 분야도 거부한다.
반환 필드에서 snapshot 제외와 최대 4행을 확인하며 전체 복원은 원래 행 수를 유지한다.

## 재현과 한계

테스트 PostgreSQL URL을 RUN_POSTGRES_INTEGRATION으로 설정한 뒤 실행한다:

```powershell
python -m scripts.benchmark_saved_context --output output/context/saved-context-benchmark.json
```

스크립트는 pg_temp 전용 search_path와 임시 테이블을 사용하고 연결 종료로 정리한다.
실제 사용자 데이터를 수정하지 않는다. 임시 테이블은 운영 스키마 전체 검증을 대신하지
않는다. 반환 행 수는 제한하지만 개별 content 길이를 SQL에서 잘라내지는 않는다.
문맥 문자열의 최종 문자 제한은 서비스가 기존 규칙대로 적용한다.
