# 기본 용어 목록과 검색 사전 통합

## 실제 문제

쉬운 법률 용어 화면은 검색어가 없을 때 `/api/catalog/{category}`의 용어를 표시하고, 검색어가 있을 때 `/api/legal/terms`를 호출한다. 두 API가 서로 다른 사전을 사용해 실행 중인 서버에서 내용증명·임차보증금·계속근로기간·하자가 목록에는 있지만 같은 이름으로 검색되지 않았다. 청약철회는 두 경로의 설명이 달랐다.

검색이 기본 목록과 같은 Backend `CATALOG[category]['terms']`를 읽도록 변경했다. 용어 이름과 설명에 포함된 검색어로 필터링하고, 목록의 명칭·설명·순서를 유지한다. 별도 사전은 제거했다. 공통 `Category` 계약으로 알 수 없는 분야를 거절하고, 앞뒤 공백을 제거한 검색어가 2자 미만이면 기존 입력 오류 형식의 HTTP 422를 반환한다.

기존 보증금·임금체불·청약철회 검색은 계속 결과를 반환한다. 보증금은 목록의 표준 명칭인 **임차보증금**으로 표시된다. 청약철회 설명도 기본 목록의 기존 설명으로 일치시킨다. 새 법률 용어·모델 호출·법률적 결론은 추가하지 않았다.

## 검증

- 수정 전 테스트 6개가 실패해 세 분야의 불일치와 입력 검증 누락을 재현했다.
- `backend/tests/test_term_catalog_search.py`는 목록의 모든 용어를 이름과 설명으로 검색하고 명칭·설명을 대조한다. 분야 격리, 없는 용어의 빈 결과, 기존 검색어와 공백 처리, 잘못된 분야와 검색어 길이를 검사한다.
- 관련 API·프론트엔드 서비스 테스트 15개를 통과했다.
- Docker 백엔드를 재빌드·재실행한 뒤, 실제 HTTP와 Streamlit `AppTest`의 용어 화면에서 세 분야의 용어 6개를 목록에서 확인하고 각각 검색했다. 화면과 API의 명칭·설명이 일치하고 화면 예외가 없음을 확인했다. 실제 브라우저의 시각적 배치를 검사한 것은 아니다.
- PostgreSQL·Redis 통합을 포함한 전체 테스트는 633개 통과, 외부 환경 선택 검사 4개 제외였다. 기존 Starlette 경고 1개가 있다.

이 사전은 일반적인 안내 문구이며 공식 법률 근거 검색이나 LLM 용어 대화와 구분한다. 이 변경은 사전 경로의 일관성 개선이며 법률 설명의 정확도를 새로 평가한 것은 아니다.
