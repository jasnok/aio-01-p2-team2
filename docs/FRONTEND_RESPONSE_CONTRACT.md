# Frontend Backend 응답 계약

공통 HTTP 클라이언트의 성공 응답은 JSON 객체입니다. 배열·문자열·숫자·불리언·null 또는 잘못된 JSON은 `BackendClientError(INVALID_RESPONSE)`로 변환합니다. 정상 객체, 204, 기존 빈 본문 처리는 유지합니다. 법률 답변과 검색 결과의 세부 필드는 기존 Pydantic 계약 검증을 계속 사용합니다.

오류 응답은 FastAPI `detail` 객체·문자열·422 목록 형식을 유지합니다. 본문 자체가 비객체이거나 `code/message`가 빈 문자열 또는 잘못된 유형이면 HTTP 상태를 포함한 일반 안내로 대체합니다. 배열·문자열 본문에서 발생하던 `AttributeError`와 비문자열 코드의 딕셔너리 조회 오류를 차단합니다. 401 인증 만료 표시 및 403·404 안내는 계속 적용합니다.

이 변경은 API 권한 정책이나 인증 방식을 바꾸지 않습니다. 서버 오류 원문을 일반 오류 안내에 덧붙이지 않으며, 정상 객체 내의 개별 업무 필드까지 모두 검증하는 변경도 아닙니다.

검증은 실제 HTTPX Response 객체로 비객체 성공, HTML 프록시 오류, 비객체 오류, 잘못된 code/message, 정상 객체, FastAPI detail, 인증 만료를 재현합니다. Streamlit AppTest는 연결 상태 화면에서 성공 배열·502 배열을 주입하여 예외나 성공 표시 없이 오류 안내가 나타나는지 확인합니다. `frontend/tests/test_backend_client.py`는 최종 30개 통과했습니다. 외부 모델 API 호출은 필요하지 않습니다.

전체 로컬 테스트는 화면 테스트 2개 추가 전 423개 통과·4개 외부 검증 건너뜀을 확인했고, 추가 후 해당 파일 30개를 다시 통과했습니다. 전체 최종 개수는 PR의 최종 CI 결과로 확인합니다.
