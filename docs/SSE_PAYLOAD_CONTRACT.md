# SSE 상태와 이벤트의 UI 반영 전 검증

실행 상태 snapshot은 객체이며 문자열 상태를 가져야 합니다. 배열·객체·불리언 상태가 집합 검사에서 `TypeError`를 발생시키던 경로를 `CONTRACT_MISMATCH` 안내로 바꿨습니다. 실행 ID, 완료 결과의 Pydantic 검증, 실제 모드 확인, 최종 상태 일치 검사는 유지합니다.

진행 이벤트는 콜백 호출 전에 실행 ID와 알려진 이벤트 이름, step 이벤트의 비어 있지 않은 문자열 ID, UI 사용 문자열 필드, 음수가 아닌 정수 결과 수, 미리보기 목록과 문자열 필드를 검증합니다. 결과 수의 null과 서버가 사용하는 tool의 null은 허용합니다. 알 수 없는 추가 필드는 기존 확장 가능성을 위해 유지합니다. 이벤트 ID는 양수여야 하며 기존 중복 제거·재연결·전체 대기 제한은 유지합니다.

서버의 `guest.storage_failed`는 분석 실패가 아닌 임시 이력 저장 실패 안내입니다. 이 이벤트를 알 수 없는 이벤트로 거부하던 문제도 수정하여 분석을 계속 수신합니다. 사용자에게 저장 실패와 분석 진행을 구분해 표시합니다.

잘못된 이벤트는 UI 콜백이나 마지막 이벤트 ID에 반영하지 않습니다. 이 검증은 수신 데이터 계약이며 서버 권한 정책, 모델 답변 품질, 네트워크 장애 복구 횟수를 변경하지 않습니다.

대상 테스트는 정상 snapshot/완료/보완 질문, 재연결 중복 제거, 비정상 상태, step·tool·stage·count·미리보기 오류의 콜백 호출 없음, 정상 null tool 및 저장 실패 이벤트를 검증합니다. 최종 대상 파일은 24개 통과했습니다. 유료 API 호출은 없습니다.
