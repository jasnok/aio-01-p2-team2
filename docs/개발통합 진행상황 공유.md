# LawPath 개발통합 진행상황 공유

> 최종 갱신: 2026-09-05  
> 기준 브랜치: `feature/frontend-local-mvp`  
> 범위: Frontend·Backend/Agent·Legal MCP·Database/RAG 공통 뼈대

## 1. 현재 단계

프로젝트는 네 파트가 같은 저장소에서 독립적으로 개발할 수 있는 디렉터리, 실행 진입점, 환경변수 예시와 계약 테스트 뼈대를 갖췄다.

```text
Frontend PC :8501
→ Backend PC :8000
→ Legal MCP PC :8011
→ DB PC PostgreSQL :5434
```

현재 Frontend는 Mock 데이터로 기능을 확인할 수 있다. Backend·MCP·DB는 모듈 골격과 일부 Mock 실행 경로가 있으나 실제 법률 데이터 기반 네 PC E2E는 아직 완료되지 않았다.

## 2. 파트별 구현 상태

| 파트 | 마련된 내용 | 현재 한계 |
|---|---|---|
| Frontend | Streamlit 화면, 3개 분야, 분석·검색·보조기능, 역할·FAQ CRUD·이력, QA | 실제 인증·Backend API 미연동 |
| Backend | FastAPI 진입점, health·legal Router, Agent Profile/Registry/Runtime, Provider·MCP Client 계층 | 실제 LLM·법률 MCP E2E 미완료 |
| Legal MCP | HTTP health, Tool·Schema·Service·Repository·Embedding·DB 계층 | 실제 pgvector 검색·정식 MCP transport 검증 필요 |
| Database | Docker 설정, `001_init.sql`, ingestion 모델과 collector/normalizer/embedder 폴더 | 공식 Seed·수집·임베딩·평가 실행 미완료 |
| 공통 계약 | API·MCP·DB 문서, JSON Fixture, 계약 테스트 | FAQ·인증·이력 API 계약 추가 필요 |

## 3. 확정 디렉터리 역할

```text
frontend/                 화면과 Backend HTTP Client
backend/                  API, Agent, 인증·권한·업무 흐름
legal_mcp/                법률 검색 Tool, Service, Repository
database/                 Migration, 수집·정규화·적재·Embedding
tests/contract/fixtures/  파트 간 요청·응답 기준 예시
docs/architecture/        현재 공통 계약
docs/development/         통합 실행 순서
docs/회의내용/            과거 논의와 참고자료
```

의존 방향은 다음과 같이 유지한다.

- Frontend는 Backend만 업무 API로 호출한다.
- Backend와 Agent는 법률 DB를 직접 조회하지 않는다.
- Legal MCP가 Repository를 통해 PostgreSQL·pgvector를 조회한다.
- 데이터 수집 파이프라인은 사용자 요청 흐름과 분리한다.
- Redis·PostgreSQL·비밀번호를 Frontend가 직접 관리하지 않는다.

## 4. 현재 공통 실행 자산

- 서비스별 `requirements.txt`와 `.env.example`
- 루트 `docker-compose.yml`, `pytest.ini`, `requirements-dev.txt`
- Backend `/health` 및 질문 API 골격
- Legal MCP `/health`와 세 Tool 모듈
- PostgreSQL + pgvector 초기 Migration
- 계약 Fixture와 자동 계약 테스트
- 팀 서버 연결 점검 UI

## 5. 팀 서버 주소

| 담당 | 서비스 | 주소 |
|---|---|---|
| 상옥 | Frontend | `http://192.100.200.232:8501` |
| 다혁 | Backend | `http://192.100.200.195:8000` |
| 병훈 | MCP | `http://192.100.200.72:8011` |
| 지혜 | PostgreSQL | `192.100.200.99:5434/legal_ai` |

비밀번호는 Git 문서와 화면에 기록하지 않는다. 실제 값은 담당 PC의 `.env`에서만 관리한다.

## 6. 통합 전 환경 확인

각 서버는 담당 PC에서 `0.0.0.0`에 바인딩하고 Windows 방화벽의 사설 네트워크 인바운드 규칙을 열어야 한다.

```text
Frontend: GET /_stcore/health
Backend:  GET /health
MCP:      GET /health
DB:       TCP 5434
```

Frontend QA 모드의 `팀 서버 연결 테스트`는 위 네 지점을 검사한다. DB는 포트 접근까지만 검사하며, 인증과 `SELECT 1`은 Backend 또는 MCP 담당 health에서 확인한다.

2026-09-05 현재 이 개발 PC에서 Backend·MCP·DB 실제 주소는 타임아웃됐다. 통합일에 서버 실행·IP·포트·방화벽·같은 네트워크 여부를 순서대로 확인해야 한다.

## 7. 자동 테스트 상태

Frontend 자동 테스트는 다음을 포함한다.

- 전체 Mock 사용자 흐름
- FAQ 작성·수정·삭제·페이지 이동
- 답변 대기 우선 정렬
- 역할별 화면과 관리자 FAQ
- 통합 이력
- 팀 연결 검사 성공·실패 처리
- 사이드바 접힘 CSS 회귀 검사

실행 명령:

```powershell
python -m pytest frontend\tests -v
python -m pytest -q
```

문서 갱신 직전 Frontend 테스트는 22개 모두 통과했다.

## 9. 팀 회의에서 반드시 확정할 내용

- MCP 실제 transport 경로와 포트 `8011`
- Backend health의 `mcp`, `database`, `redis` 상태 정의
- Frontend 응답 View Model과 오류코드
- FAQ·질문 CRUD·페이지네이션 API
- 답변 상태는 `PENDING`, `ANSWERED` 두 종류만 사용할지
- 인증 Cookie, 회원·비회원 소유권, 관리자 권한
- 비회원 질문 7일 만료 처리 주체와 삭제 작업
- Redis 운영 PC, Key, TTL과 장애 시 동작
- PostgreSQL Migration 담당과 Supabase 백업 방식
- CORS 허용 Origin과 Timeout·재시도 값
