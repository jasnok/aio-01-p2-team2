# 실행 스냅샷의 버전과 전이 계약

## 배경

Issue #88에서 조회 타임아웃의 완료 결과 덮어쓰기를 수정했다. 그러나 작업자의 일반
저장은 무조건 SET이므로, 이전 버전의 작업자가 최신 결과를 덮어쓰거나 만료된 키를
재생성할 수 있었다. Issue #90은 저장 전체에 원자적 계약을 적용한다.

## 계약

- 신규 예약은 실행 스냅샷과 멱등 예약을 같은 Lua 호출에서 만들고 revision 1을 부여한다.
- 저장은 현재 revision과 작업자가 가진 revision이 같아야 성공한다. 성공하면 1 증가한다.
- 기존 revision 없는 스냅샷은 0으로 해석한다. 기존 API 응답에는 revision을 추가하지 않는다.
- run_id, 소유자, actor, 질문·분야, 저장 선택, 대화 ID, 생성 시각은 바꿀 수 없다.
- 기존 SSE 이벤트는 삭제·재작성할 수 없다. 이벤트 ID는 1부터 연속 증가한다.
- 완료·추가 정보 요청은 결과가 필요하고, 실패는 오류 정보가 필요하다.
- completed, stopped, failed는 변경할 수 없다. 내용이 동일한 종료 상태 저장은 TTL을
  연장하거나 revision을 증가시키지 않는 무변경 성공으로 처리한다.
- 만료된 키는 작업자 저장으로 다시 만들지 않는다. 신규 생성 경로는 예약뿐이다.

| 현재 상태 | 허용된 다음 상태 |
|---|---|
| queued | queued, running, failed |
| running | running, completed, stopped, failed |
| completed / stopped / failed | 동일한 내용의 저장만 허용 |

조회 중단 판정은 기존 원문 비교를 유지하며 revision도 증가시킨다. 따라서 조회가 먼저
중단 상태를 확정했으면 이전 작업자의 후속 저장은 거부된다. 조회의 TTL은 유지하고,
일반 진행 저장은 기존과 같이 설정된 TTL을 갱신한다.

## 충돌 처리

충돌은 저장소 연결 장애와 구분한다. 작업자는 최신 스냅샷을 채택하고 로컬 실행 상태를
제거하여 추가 작업을 중단한다. 충돌 이후 실패 상태를 다시 쓰는 루프는 없다.
로그에는 실행 ID와 고정된 거부 사유만 남기며 최신 스냅샷의 질문·결과는 출력하지 않는다.
타임아웃 처리도 이미 종료된 로컬 결과를 실패로 바꾸지 않는다.

Lua는 JSON을 해석해 검증하지만 Python이 만든 원문을 저장한다. Lua cjson의 빈 배열
재인코딩으로 `[]`가 `{}`로 바뀌는 문제를 피하고 중첩된 결과의 배열 형식을 보존한다.

## 검증과 실행

`backend/tests/test_agent_run_store.py`는 실제 Redis에서 동시 예약, revision 경합,
소유자 변경, 상태 역행, 이벤트 삭제·재작성·번호 누락, 필수 결과·오류 누락,
종료 상태 보호, TTL, 만료, legacy revision 및 중첩 빈 배열 보존을 검증한다.
`backend/tests/test_agent_run_timeout.py`는 시작·진행·완료·타임아웃 경로의 충돌 처리를 검증한다.

CI는 별도 Redis 7 서비스를 띄우고 `RUN_REDIS_INTEGRATION`으로 통합 테스트에만 연결한다.
일반 회귀 테스트는 mock 설정을 유지한다. 로컬에서는 해당 변수에 테스트 Redis URL을
명시하여 실행한다. 무작위 테스트 전용 키만 정리하고 실제 사용자 키는 삭제하지 않는다.

## 설계 근거와 한계

`C:\mini_multi_agent`의 검증 대상 revision 계약과 `C:\aidevs`의 명시적 상태·종료
guard를 참고했다. 현재 서비스는 결정적 Workflow이며 새 LLM Supervisor를 추가하지 않았다.
저장 경쟁의 승자는 Redis의 원자적 처리 순서로 결정된다. revision은 작업자 lease,
LLM 호출의 exactly-once 실행, DB 이력 저장과 Redis의 분산 트랜잭션을 보장하지 않는다.
충돌 전 시작된 외부 호출·이력 저장의 부작용을 되돌리지 않으며 Redis 장애 후 자동 복구나
프로세스 재시작 후 작업 자동 재개도 제공하지 않는다. 이력 저장의 멱등성과 작업 lease는
별도 신뢰성 과제다.
