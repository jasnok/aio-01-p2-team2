# LawPath
생활 속 법률 문제를 AI가 정리하고, 관련 법령과 사례를 찾아주는 서비스입니다.

> “퇴직했는데 퇴직금을 못 받았습니다. 어떤 법을 확인해야 하나요?”

법률 용어를 몰라도 자신의 상황을 일상적인 문장으로 입력할 수 있습니다. AI가 핵심 쟁점을 정리하고, 저장된 법률 자료에서 참고할 근거를 찾아 보여줍니다.

## 무엇을 할 수 있나요?

1. **내 상황 분석** — 임대차·주거, 근로·임금, 소비자·중고거래 중 분야를 선택하고 질문합니다.
2. **관련 근거 확인** — 법령·법원 판례·소비자 상담사례를 구분해 보고, 필요한 내용만 펼쳐 읽습니다.
3. **이해와 보관** — 어려운 법률 용어를 추가로 질문하고, 분석 결과를 PDF로 내려받습니다. 회원은 저장한 내용을 질의 이력에서 확인할 수 있습니다.

분석 중에는 진행 상태를 보여주며, 정보가 부족하면 추가로 확인할 내용을 안내합니다.

## 개인 포트폴리오로 발전시킨 부분

4인 팀 프로젝트를 기반으로, 제가 담당한 프론트엔드와 이후 개인 실행 환경 개선을 정리한 저장소입니다. 전체 서비스를 혼자 개발한 프로젝트는 아닙니다.

| 구분 | 작업 내용 |
|---|---|
| 팀 프로젝트 담당 | 프론트엔드 화면 구성과 백엔드 API 연결 |
| 사용자 경험 개선 | 분석 진행 표시, 근거 자료 접기·펼치기, 추가 질문, PDF 다운로드, 저장·이력 화면 |
| 개인 확장 | 팀 서버 없이 실행하도록 Docker로 서비스들을 묶고, 실제 검색 데이터가 포함된 DB 초기화 환경 구성 |
| 개인 AI 개선 | 문서별 최고 청크 보존, 핵심 검색어 추출, 가중합·RRF 비교, 반복 임베딩 캐시 |
| 개인 신뢰성·운영 개선 | 주장별 근거·원문 인용 검사, 생성 실패 상태 표시, 단계별 시간·답변 생성 토큰 기록, Redis 실행 상태·SSE 보관 |

팀 역할: 장상옥(프론트엔드) · 임다혁(백엔드·AI Agent) · 오병훈(MCP 검색) · 박지혜(DB·데이터).

## 어떻게 동작하나요?

```text
사용자가 상황 입력
  → AI가 질문을 분석하고 필요한 검색 요청
  → DB에서 관련 법령·판례·상담사례 검색
  → 답변과 참고 자료를 화면에 표시
```

- **화면:** Streamlit — 질문 입력과 결과 표시
- **분석 서버:** FastAPI·OpenAI — 질문 판단과 답변 생성
- **검색 연결:** MCP — AI와 검색 기능 연결
- **데이터 저장:** PostgreSQL·pgvector — 법률 자료와 의미 기반 검색
- **임시 저장:** Redis — 실행 상태와 비회원 임시 이력 관리

## 내 컴퓨터에서 실행하기

Docker Desktop과 OpenAI API 키가 필요합니다. AI 사용 시 API 비용이 발생할 수 있습니다.

1. 저장소를 내려받습니다.
2. `frontend/`, `backend/`, `legal_mcp/`, `database/`의 `.env.example`을 각각 `.env`로 복사하고 API 키와 DB·Redis 비밀번호를 설정합니다. 기존 `.env`는 덮어쓰지 않습니다.
3. 프로젝트 폴더에서 아래 명령을 실행합니다.

```bash
docker compose -f compose.yml up --build -d
```

브라우저에서 **http://localhost:8501**을 열면 됩니다. API 키와 비밀번호가 담긴 `.env`는 공유하지 않습니다.

처음 생성하는 빈 DB에는 실제 검색 자료가 자동으로 들어갑니다. 기존 DB가 있다면 자동으로 덮어쓰지 않습니다.

## 데이터와 개선 과제

포함된 검색 데이터는 **법령 8건·판례 16건·소비자 상담사례 678건**, 총 702건입니다. 사용자 개인정보나 대화 이력은 초기 데이터에 포함하지 않습니다. [데이터 구성 확인](database/seed/DATA_MANIFEST.md)

검색 데이터가 제한적이므로 분야별 결과가 부족하거나 관련성이 낮을 수 있습니다. 앞으로 자료 범위를 늘리고, 질문과 근거의 관련성 평가 및 다른 PC에서의 전체 실행 검증을 보완할 계획입니다. 같은 데이터를 사용해도 AI 답변은 달라질 수 있습니다.

## 개인 리팩토링 검증 — 2026-10-01

기존 코드를 기준선으로 보관하고 동일 DB 스냅샷에서 검색 방식과 키워드 SQL을 비교했습니다.

- 회귀 테스트: 257개 통과, 명시적 실행이 필요한 기존 실서버 통합 테스트 4개 제외. 실제 서버 확인은 별도 스모크 스크립트와 브라우저로 수행합니다. 실제 최종 4건은 주거·근로 LLM 답변 2건, 소비자 인용 검증 실패에 따른 대체 답변 1건, 정보 부족 보완 안내 1건으로 기록됐습니다.
- 검색 비교: 법령명·사건번호 15개는 기존·개선 가중합·RRF 모두 상위 3개 안에서 대상 문서를 찾았습니다. 자연어 질문 15개 중 12개의 순위가 바뀌었으며, 관련성은 별도 수동 검토 대상입니다. 검색 품질 향상이나 법률 정답률로 해석하지 않습니다.
- 키워드 SQL: 문서 본문을 청크마다 반복 검사하던 부분을 문서당 한 번 검사하도록 변경했습니다. 단일 paired 실행에서 주택임대차보호법 8,286→75ms, 퇴직금 288→27ms, 환불 1,007→81ms였고 문서·점수·청크 결과가 같았습니다. 전체 서비스 응답 시간이나 통계적 p95를 의미하지 않습니다.
- 답변: 주장의 인용 ID와 원문 인용을 함께 반환하고 원문에 없는 인용은 대체 답변으로 종료합니다. 인용문 존재 검사는 법적 타당성이나 주장 전체의 함의를 보장하지 않습니다.
- 실행: 실제 모드의 완료 결과·SSE 이벤트를 Redis에 TTL 동안 보관하며, 동일 요청 키의 원자적 예약·소유자 분리·재조회 경로를 검증합니다. 작업 큐를 통한 중단 작업 자동 재개는 포함하지 않습니다.

완료 결과 4건이 API 컨테이너 재생성 후에도 동일하게 조회되는 것을 확인했습니다. 소비자 질문의 인용 생성 안정성과 자연어 검색 관련성은 후속 개선 대상입니다.
