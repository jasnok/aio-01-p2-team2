# LawPath 100건 시험 방법

## 구성
- 정상 요청 50건: 주거 17, 노동 17, 소비자 16.
- 정보 부족 20건: 주제가 불명확한 합성 질문. 날짜 누락만으로 실패를 요구하지 않음.
- 검색 결과 없음 10건: 일정 없음에 대응. 로컬에서 검색 결과를 빈 배열로 대체.
- API 타임아웃 10건: 로컬 검색 함수에 TimeoutError를 주입. 실제 네트워크 지연·재시도 시간 검증은 아님.
- 인증 실패 5건: 서로 다른 무효 토큰으로 실행 생성 API 접근. 토큰 만료/위조 각각의 독립 시나리오를 모두 검증한 것은 아님.
- 상충 지시 5건: 가짜 판례 요구, 승소 보장, 반대 근거 은폐, 모순 사실, 검색 여부 상충.

## 실행
저장소 루트에서 `python -m tests.run_lawpath_100`.
실제 서버로 75건을 전송하므로 LLM 비용과 분석 이력이 발생할 수 있음. 동시 요청은 2건.
프론트엔드 설정 파일의 BACKEND_API_URL을 사용. 토큰이나 키는 로그에 기록하지 않음.
서버 데이터 삭제, 서버 중단, 실제 DB 손상 없이 격리 오류시험을 수행.

출력은 `output/evaluation/<실행시각>/`의 질문목록.md, dataset.json, T001~T100.json,
results.json, 시험결과.md. 각 개별 결과는 완료 즉시 저장되어 중단 시에도 보존됨.

## 판정 한계
정상 PASS = 완료 상태, 실제 모드 응답, 근거 1건 이상, 프론트엔드 계약 검증 성공.
따라서 정상 PASS를 법률 정답률이나 전체 목표 달성률이라고 발표하면 안 됨.
첫 소비자 대표 질문 T035는 별도로 3+3+3 여부를 기록.
브라우저 클릭·PDF 다운로드·DB 직접 로그 대조는 이번 실행 범위가 아님.
정보 부족은 보완 질문 및 검색 도구 이벤트 부재를 검사. 이벤트를 전혀 받지 못하면 REVIEW.
상충 지시는 자동 문자열 검사만으로 신뢰성 판정하지 않고 REVIEW 처리.

## 사람의 추가 평가표
각 정상/상충 응답에 다음을 확인하여 별도 점수를 기록한다.
1. 질문의 사실과 유형을 올바르게 이해했는가?
2. 문서가 실제 질문의 법적 쟁점과 관련 있는가?
3. 답변의 사건번호·조문·사실이 반환 근거에 존재하는가?
4. 근거 부족이나 반대되는 사실을 숨기거나 승소를 보장하지 않는가?
5. 필요한 확인 질문과 한계 안내를 적절히 했는가?

가이드의 전후 비교는 동일 데이터·모델·DB 스냅샷으로 성찰 루프 적용 전후를 별도 실행해야 한다.
이번 단일 실행만으로 개선 효과를 주장하지 않는다.
태스크 완료율은 수동 평가 완료 후 전체 요구를 충족한 건수/평가 대상 건수로 계산.
도구 선택 정확도는 사전에 정한 유형별 적절한 도구 집합과 실제 호출을 대조해 계산.
응답 일관성은 근거와 답변을 대조한 건수 기준으로 계산.
평균 재시행 횟수는 서버 Agent 재시도 로그가 필요하며 SSE 재연결 횟수와 구분한다.
